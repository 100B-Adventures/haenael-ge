# 인프라와 시크릿 인벤토리

> 값은 여기 쓰지 않는다. 이름, 용도, 어디에 있는지만 쓴다 (하네스 §4.5).
> 최종 확인 2026-08-28. 확인 방법은 맨 아래에 있다.

> **현재 배포 드리프트**: `haenael-ge.vercel.app`은 1.0.0, main 배포 주소는 1.2.0을 반환한다. Supabase migration은 `20260825020000`만 운영에 없다. 이 문서는 구성 인벤토리이며 최신 출시 판정은 [제품 현재 상태](../../2-product/current-state.md)를 따른다.

## 왜 이 문서가 생겼나

2026년 8월 25일, 환전 신청이 네 번 연속 실패했다. 원인은 `SUPABASE_SERVICE_ROLE_KEY`가
Vercel 운영 환경에 등록되지 않은 것이었다. **어떤 키가 어디에 왜 있어야 하는지 적어둔
문서가 없어서** 빠진 것을 아무도 눈치채지 못했고, 찾는 데 네 턴이 걸렸다.

---

## 이 문서의 자리

**설계는 `docs/architecture.md` 가 정본이고, 이 문서는 운영 실태가 정본이다.**

| 무엇을 알고 싶나 | 어디를 보나 |
|---|---|

| **어떤 키가 어디에 있나, 없으면 무슨 일이 나나** | **이 문서** |
| 지금 운영에 무엇이 올라가 있나 | `RELEASE.md` |

새 키를 도입하면 이 문서에 한 줄 추가한다. 설계가 바뀌면 그쪽을 고친다.

## 1. 구성

| 층 | 무엇 | 어디 |
|---|---|---|
| 웹 | Next.js 16 App Router | Vercel (`haenael-ge`, 팀 `100-b`, 리전 icn1) |
| 데이터베이스 | Postgres 17.6 | Supabase (`gmpwrcxpvgylmllasoqy`, 서울) |
| 로그인 | Supabase Auth + 카카오 | Supabase |
| 서버 함수 | Deno Edge Functions 11개 | Supabase |
| 결제 | 토스페이먼츠 | 외부 |

| 관리자 통지 | 슬랙 웹훅 | 외부 |

**운영 주소**: `haenaelge.vercel.app` → `haenael-ge.vercel.app`. 2026-08-28 현재 두 주소 모두 1.0.0 배포로 연결되고, 최신 main 1.2.0은 별도 주소에 있다.

## 2. 시크릿이 사는 곳 세 군데

같은 이름이 여러 곳에 있을 수 있다. **용도가 다르므로 양쪽 다 둔다.**

| 위치 | 누가 읽나 | 넣는 법 |
|---|---|---|
| Vercel 환경변수 (Production) | 웹 서버 코드 | `vercel env add <이름> production` |
| Supabase Edge Function secrets | 서버 함수 | `supabase secrets set` |
| 로컬 `~/.sj-agent-harness/secrets/haenael-ge.env` | 개발 세션 | 직접 작성. 권한 600, git 미추적 |

---

## 3. Vercel 운영 환경변수

| 이름 | 용도 | 없으면 |
|---|---|---|
| `SUPABASE_SERVICE_ROLE_KEY` | 서버가 데이터베이스에 전체 권한으로 붙는다 | **환전 신청이 통째로 죽는다** |
| `NOTIFY_INTERNAL_TOKEN` | 웹 서버가 알림 Edge Function을 내부 호출할 때 쓰는 공유 토큰 | 환전 알림 호출이 401/403으로 거부된다 |
| `NEXT_PUBLIC_SUPABASE_URL` | 데이터베이스 주소 | 아무것도 안 된다 |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | 브라우저에서 본인 데이터만 읽는다 | 로그인 불가 |
| `CASHOUT_ACCOUNT_ENCRYPTION_KEYS` | 계좌번호 암호화 키 묶음 (JSON) | 환전 신청 거부 |
| `CASHOUT_ACCOUNT_ACTIVE_KEY_VERSION` | 지금 쓸 암호화 키 번호 | 환전 신청 거부 |
| `CASHOUT_ACCOUNT_FINGERPRINT_KEY` | 계좌 중복 판별용 지문 키 | 환전 신청 거부 |
| `CASHOUT_ALLOWED_MEMBER_IDS` | D-017 세무 확정 전 환전을 시험할 회원 UUID 목록. 서버 전용, 쉼표 구분 | **기본 거부되어 모든 회원의 신규 환전 신청이 닫힌다** |
| `CASHOUT_ENABLED` / `NEXT_PUBLIC_CASHOUT_ENABLED` | 환전 기능 켬끔 | 화면이 준비중으로 보인다 |
| `NEXT_PUBLIC_PAYMENTS_ENABLED` | 결제 기능 켬끔 | 결제창이 안 열린다 |
| `NEXT_PUBLIC_TOSS_CLIENT_KEY` | 토스 결제창 | 결제 불가 |
| `NEXT_PUBLIC_KAKAO_REST_API_KEY` | 카카오 로그인 | 로그인 불가 |
| `NEXT_PUBLIC_GA_MEASUREMENT_ID` | 방문 분석 | 통계만 안 쌓인다 |
| `NEXT_PUBLIC_APP_URL` / `NEXT_PUBLIC_APP_VERSION` | 링크 생성, 버전 표시 | 링크가 어긋난다 |

`NEXT_PUBLIC_` 이 붙은 것은 **브라우저까지 내려간다.** 비밀이어야 하는 값에는 절대
이 접두사를 붙이지 않는다.

| 이름 | 용도 |

| `SUPABASE_URL` · `SUPABASE_ANON_KEY` · `SUPABASE_SERVICE_ROLE_KEY` | 함수가 데이터베이스에 붙는다 |

| `KAKAO_ALIMTALK_API_KEY` · `_API_SECRET` · `_API_URL` · `_FROM` · `_PFID` | 알림톡 발송 |
| `KAKAO_ALIMTALK_TEMPLATE_CHEER_RECEIVED` | 응원 받음 템플릿 |
| `KAKAO_ALIMTALK_TEMPLATE_CASHOUT_REQUESTED` | 환전 신청 접수 템플릿 |

| `SLACK_WEBHOOK_URL` | 관리자 통지 |
| `NOTIFY_INTERNAL_TOKEN` | 웹 서버와 공유하는 알림 내부 호출 토큰 |
| `LEAD_RATE_LIMIT_SALT` | 문의 폼 남용 방지 |
| `CASHOUT_ENABLED` · `PAYMENTS_ENABLED` | 기능 켬끔 |

## 5. 키 종류를 헷갈리지 말 것

Supabase가 지금 네 종류를 준다. **섞어 쓰면 조용히 거부당한다.**

| 종류 | 형태 | 용도 |
|---|---|---|
| `anon` (legacy) | 208자 JWT | 브라우저. 본인 데이터만 |
| `service_role` (legacy) | 219자 JWT | 서버. 전체 권한 |
| `publishable` (신형) | 46자 | anon 대체 |
| `secret` (신형) | 41자 | service_role 대체 |

**2026-08-25 확인된 함정**: `notify` 함수가 받은 토큰을 자기 환경변수와 문자열로
직접 대조한다. Supabase 안에서 부르면 자동 주입값이라 일치하지만, Vercel 웹에서
legacy `service_role` 키로 부르면 값이 달라 403으로 거부된다. **응원 알림은 되고
환전 알림만 0건인 이유가 이것이다.**

## 6. 확인하는 법

값은 안 보인다. 이름과 존재 여부만 나온다.

```bash
# Vercel 운영 환경변수 목록
npx vercel env ls production

# Supabase 함수 secrets 목록
npx supabase secrets list --project-ref gmpwrcxpvgylmllasoqy

# 어떤 키 종류가 있는지
npx supabase projects api-keys --project-ref gmpwrcxpvgylmllasoqy
```

배포 전에 **그 기능이 필요로 하는 환경변수가 대상 환경에 다 있는지** 확인한다.
이것을 안 해서 8월 25일에 막혔다.

## 7. 규율

1. 값을 저장소, 위키, 채팅, 로그, 커밋에 원문으로 쓰지 않는다.
2. 로컬 보관은 `~/.sj-agent-harness/secrets/*.env`. 권한 600, 폴더 700, git 미추적.
3. 새 키를 도입하면 이 문서에 한 줄 추가한다. 이름과 용도만.
4. 운영 스키마는 마이그레이션 파일로만 바꾼다. 콘솔에서 직접 만지지 않는다.
   2026-08-25에 마이그레이션 열두 건이 기록과 실제가 어긋나 있었다. 콘솔 직접
   변경이 원인이다.
5. 비밀이어야 하는 값에 `NEXT_PUBLIC_` 을 붙이지 않는다.
