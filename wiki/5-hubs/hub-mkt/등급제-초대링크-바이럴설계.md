## 1. 왜 이 기능인가

`docs/bm.md:61,63` 이 못 박은 생존 전제 — **"CAC ≈ 0. 자가확산이 안 되면 유료 마케팅으로는 LTV<CAC."**
그런데 레포 실측 결과 **초대·추천 인프라가 0건**이다(`referral`/`invite`/`추천인`/`초대` 코드 없음). 공유 컴포넌트만 존재(`WordmapShareIcons.tsx`, `ShareLinkCard.tsx`, `MyLinkCard.tsx`).

즉 **생존 전제를 실행할 장치가 제품에 없다.** 이 문서가 그 갭을 메운다.

핵심 아이디어: **성장을 현금이 아니라 마진으로 산다.** 광고비는 성과와 무관하게 선지출이지만, 수수료 할인은 사용자가 실제로 환전할 때만 발생한다. 성과 연동 마케팅비다.

## 2. 두 축의 보상

초대 성사 수에 따라 등급이 오르고, 등급은 **두 가지**를 준다.

| 축 | 내용 | 스프린트 |
|---|---|---|
| **① 수수료 인하** | 등급이 오를수록 환전 수수료가 낮아진다 | **이번 스프린트** |
| **② UI 선택권** | 등급이 오를수록 목표 페이지 꾸미기 옵션이 열린다 | **다음 스프린트 (이 문서)** |

### 왜 UI 선택권이 수수료보다 나을 수 있나
- 수수료 인하는 **환전하는 사람에게만** 가치가 있다. 아직 환전할 만큼 못 모은 사람에게는 보상이 아니다.
- UI 선택권은 **목표를 만든 순간부터** 가치가 있다. 초기 사용자에게 훨씬 빨리 닿는다.
- 꾸민 페이지는 그 자체가 **공유 유인**이다. 보상이 확산을 다시 만드는 되먹임 구조.
- 한계비용이 0에 가깝다. 수수료 인하는 매출을 깎지만 테마 해금은 안 깎는다.

## 3. UI 선택권 후보 (다음 스프린트에서 확정)

| 등급 | 해금 후보 |
|---|---|
| 기본 | 현행 기본 테마 |
| 1단계 | 목표 페이지 배경 색상 선택 |
| 2단계 | 워드맵 색 팔레트 선택 |
| 3단계 | 목표 페이지 커버 이미지 업로드 |
| 최고 | 전용 배지 + 커스텀 링크 주소 |

⛔ 확정 전 검토 필요: 커버 이미지 업로드는 **부적절 이미지 신고·검수 부담**을 만든다(`docs/risks.md` 신고 체계와 연동 필요). 배경/팔레트 같은 **선택형(자유 업로드 아님)** 먼저 여는 것이 안전하다.

## 4. 초대 성사의 정의 (어뷰징 방어 핵심)

**보상은 검증 가능한 행동에만 건다.**

| 행동 | 검증 가능? | 보상 |
|---|---|---|
| 공유 버튼 클릭 | ❌ 실제 게시 여부 확인 불가 | 보상 없음 |
| 초대 링크 클릭 | ❌ 자기 클릭 반복 가능 | 보상 없음 |
| **초대받은 친구가 가입 + 목표 생성 + 결제된 응원 1건 이상 수령** | ✅ 전부 DB에 남음 | **1명당 등급 상승** |

마지막 조건이 방어의 핵심이다. 가짜 계정으로 등급을 올리려면 **본인이 실제로 돈을 써야 한다.** 수수료 몇 %p를 아끼려고 실결제를 하는 건 수지가 안 맞는다.

관련: `docs/architecture.md` §2.5 ACCEPTED-RISK — 셀프후원·자금세탁 차단 미구현. 등급제 도입 시 이 리스크가 커지므로 **셀프후원 탐지를 같이 올려야 한다**(같은 결제수단·같은 기기로 자기 목표에 응원 등).

## 5. 필요한 인프라 (현재 0)

- 초대 코드 발급·저장 (회원당 고유 코드)
- 가입 시 초대 코드 연결 (`auth-kakao` 경유)
- 초대 성사 판정 (친구의 목표 생성 + 결제 응원 수령 시점에 카운트)
- 등급 계산·저장 (회원 등급 필드)
- 환전 시 등급별 요율 적용 (`create_cashout_request` RPC)
- 등급·초대 현황 화면
- 약관 개정 (변동 요율 명시)

## 6. 이번 스프린트에서 미리 잡아둘 것

실제 초대 기능은 다음 스프린트지만, 약관과 DB 구조는 향후 등급별 변동 요율을 수용할 수 있어야 한다. 현재 전원 고정 요율은 10%이고, 등급제 도입 전까지 변동 요율은 적용하지 않는다.

- **과거 상태(2026-07-31)**: `cashout_request.fee_krw`는 리터럴 `0`이었고, 약관은 고정 5%를 표기했다.
- **현재 상태(2026-08-21)**: 두 환전 RPC는 이용료 10%+부가세를 계산하도록 로컬 구현됐다(`20260821000000_cashout_service_fee_10pct.sql`). 약관도 10%로 갱신됐다. 단, 마이그레이션은 운영 DB 미적용이다.
- **향후 상태**: 등급제를 도입할 때 회원 등급별 요율을 안전하게 적용할 구조로 확장한다.
- 회원 등급 필드 자리 확보

## 7. 열린 질문

- 등급은 **영구**인가 **기간제**인가? (영구면 초기 사용자가 유리하게 고착, 기간제면 지속 초대 동기)
- 초대한 친구가 탈퇴하면 등급이 내려가는가?
- 등급 상승을 **응원자에게도** 줄 것인가? 현재 응원자는 결제 후 아무 보상이 없다.

## 이용료 정책 결정 (회장 2026-08-21)

- **당분간 전원 10%.** 근거: 3만원 환전 시 실수령 25,819원(86.1%)이라야 거부감이 적다는 회장 판단. 지금은 등급이 없으므로 구현할 것이 없다.
- **회원수·거래 규모가 커지면 기본을 20~30%로 올리되, 친구 초대·등급 달성자는 10%를 유지**한다. 인상 자체가 초대 동기가 되는 구조.
- 순서 근거: 처음부터 20~30%로 열고 깎아주는 방식은 첫 사용자가 가장 높은 요율을 먼저 만나 이탈한다. 10%로 열고 나중에 올리면 초기 사용자는 계속 10%를 누린다.
- **인상 전 필수**: 요율 인상은 약관 불리 변경이라 사전 고지 기간이 필요하다.
