## 0. 이 문서의 앵커 (비어 있으면 스프린트 미개시)

```
PAYMENT_OPEN_DATE: (미기입 — 결제 실동작 테스트 1건을 직접 관찰한 날짜를 기입. 기입 = 스프린트 SW1 개시)
```

- 결제 오픈은 제품(build/QA/배포) 완료에 종속. 캘린더 W7과 어긋나면 **주차 시프트는 회장 승인 사안**([content-calendar-90d §3 P2](content-calendar-90d.md) 동일 회수).
- 비어 있으면: §7의 "오픈 전 준비 액션"만 수행. 결제 언급 콘텐츠 발행·응원자 면 결제 카피 사용 금지(없는 기능 광고 = 신뢰 사망).

## 1. 전환 퍼널 정의 — 유입에서 1회경험까지 5단

**구조적 사실 (이 퍼널의 제1원리)**: 응원자(결제자)는 광고로 못 사온다. **응원자 풀 = 선언자의 지인뿐**이다(persona.md 양면 매칭 — 민지는 도경의 동창이라서 결제한다). 따라서 결제를 늘리는 유일한 상류 레버는 ①선언자 수 ②선언 카드 공유율 ③공유가 닿는 지인의 질이며, 브랜드가 응원자에게 직접 할 수 있는 일은 **도달한 응원자의 전환율(카피·마찰·앵커)** 하나다.

| 단 | 전환 행동 | 담당 면 | 사용 카피 (ID) | 계측 이벤트 (GA4/DB — [architecture.md §6](../../../docs/architecture.md) 실정의) |
|---|---|---|---|---|
| ① 유입 | 콘텐츠/DM → 링크 클릭 → 방문 | 브랜드공개 | 채널: [channel-identity-kit](../../1-team-brand/channel-identity-kit.md) · DM: [dm-outbound S1~S5](dm-outbound-playbook.md) | GA4 `Active users`·`first_visit` + UTM(`utm_source=instagram\|threads\|dm`) |
| ② 선언 작성 | 방문 → 목표 생성(write-first 온보딩) | 주인공 | P2-01(카드·hero) · P2-06(문턱 낮추기) · P2-09(발행 토스트) | `goal_created` |
| ③ 공유 | 선언 카드/링크를 지인에게 노출 | 주인공 — **돈 언어 0** | P2-01(카드) + 신규 FR-S1~S3(§1-1) | DB `share_event`(실재 테이블) — GA4 `goal_shared` 추가 제안은 [kpi-runbook §3-2](kpi-runbook.md) 승계 |

- ⑤가 "첫 매출"의 완성이다 — 결제가 났어도 선언자가 수취를 인지 못 하면(알림 미도달) 루프(더 자주 인증→더 많은 응원자 유입)가 안 돈다.
- 환전(cash-out)은 이 플레이북 범위 밖(첫 4주 내 최소 환전액 도달 가능성 낮음). 환전 카피는 P4-07 — 단 ⛔ 회수 2(수수료율) 확정 전 발행 금지 유지.

### 1-1. 공유 유도 스크립트 (신규 — 주인공 면, 돈 언어 0 절대)

③단이 이 퍼널의 최다 사망 지점이다("쟤 돈 걷네" 역화 = 공유 사망, `brain://concept-공유장벽-선언vs요청-UGC바이럴`). 그래서 공유 유도는 **응원·돈을 한 글자도 언급하지 않고, 선언 자체의 가치(지켜보는 사람)만 판다.**

|---|---|---|---|---|

| FR-S3 | "본계가 부담스러우면 공부 계정에만 올려도 돼요. 보여줄 사람을 고르는 것도 선언의 일부예요." [실험] | 대화 | 공유 화면 보조 문구 | 불안 제거 — 도경형 "부모님껜 비밀" 발각 공포 해제. 본계 강요 금지 |

## 2. 첫 결제 10건 스프린트 (4주 — PAYMENT_OPEN_DATE 기점 SW1~SW4)

**북극성**: 4주 내 유료 응원 결제 `payment_success` **누적 10건** (팀/관계자 결제 제외 — ⛔ 회수 3). 캘린더 P2(W7~W10)와 같은 구간의 **결제 전환 전용 오버레이**다 — 발행·DM 볼륨은 캘린더가 정본, 이 문서는 전환 액션만 얹는다.

### 2-1. 역산 모델 [실험 — 전 수치 가설, 주간 실측으로 교체]

```
결제 10건 ← 목표페이지 방문 ~330 × 방문→결제시작 5% × 시작→완료 60%
목표페이지 방문 330 ← 공유 선언자 25명 × 공유당 평균 도달·클릭 ~13회
공유 선언자 25명 ← 활성 선언자 50명(P1 게이트 40~60 중간값) × 공유율 50%
```

병목이 어디서 터지는지 매주 이 체인 순서대로 확인한다(§2-4 진단표). **이 산술이 말하는 것: 첫 결제의 생사는 결제창이 아니라 "선언자 50명이 실제로 존재하고 실제로 공유하는가"에 이미 절반이 결정돼 있다.**

### 2-2. 주차별 액션

| 주차 | 결제 목표(누적) | 액션 (전부 실행형) |
|---|---|---|

| **SW1** (오픈 주) | **1~2건** | ① 테스트 결제 1건 직접 관찰 → PAYMENT_OPEN_DATE 기입 ② 오픈 공지: 스레드=슬로건 노출면 O(수수료 서사 회차 S1 우선 배치 — 캘린더 W7 정합) / 공스타=주인공 면이므로 **돈 언어 0으로 재작성** ③ 기존 선언자 전원에게 개인화면 알림(P4-02 준용: "친구들이 마음을 두고 갈 수 있게 됐어요") — **"친구들에게 알리세요" 류 요청 문구 절대 금지**(주인공이 결제를 홍보하는 순간 "쟤 돈 걷네" 역화. 결제 발견은 응원자가 목표 페이지에서 스스로 하게 둔다) ④ 미공유 선언자에게 FR-S2 리마인드 1회 |

### 6-2. 발행 전 자가검증 grep (산출물 파일에 실행 — 이 플레이북 자체는 규칙 인용문이라 제외)

```bash
# ① 전 산출물 공통 — 금지어 스캔 (힛 0 = 통과. 힛이 따옴표 속 관습 인용이면 예외 판정 후 기록)
grep -nE '쏘(다|ㄴ|고|면|겠)|플렉스|기부|도와주세요|후원 부탁|후원해|랭킹|TOP|1등|상금|벌금|내기|코인|캐시|포인트|화이팅' <파일>

# ② 주인공 면 산출물(선언 카드·공유 화면·FR 계열·공스타 캡션) — 돈 언어 0 검증 (힛 0 = 통과. '클로버' 힛은 검토: 공유 카드에는 인원수만)
grep -nE '돈|후원|도네|환전|현금|금액|결제|수수료|계좌|입금|₩|원[을을이 ]|클로버' <파일>

# ③ 응원자 면 산출물 — 요청형 스캔 (힛 0 = 통과)
grep -nE '주세요|부탁|해주시|해줘|도와|한 번만|제발' <파일>
```

②·③은 형태소 기반이 아니라 과탐지가 있다 — **힛 = 자동 반려가 아니라 육안 판정 의무**. 단 판정 없이 발행하면 위반.

4. **응원자 대기 장치** [실험 — 제품 기능 제안이므로 임의 구현 금지, 제안만]: 무결제 기간 목표 페이지에 "응원이 열리면 알려드릴게요" 알림 신청 1탭. 오픈 시 이들이 첫 결제 후보 풀. 구현 여부는 build 회수.
5. **카피·앵커 사전 확정**: §3 C 계열·§4 3단 앵커를 결제 UI 문구로 넘겨 build에 전달(발행 아님 — 준비).
6. **계측 사전 대조**: GA4 이벤트 5종 자리(architecture.md §6) 구현 여부 목록화 — 미구현분은 SW0 전 요청.

## 셀프심문 (CoVe + 레드팀 — 결론 직전 자가 반박)

**Q1 (지정 질문). "이 플레이북대로 4주 돌려서 첫 결제가 안 나온다면 가장 유력한 이유는?"** — **답: 결제창이 아니라 상류 — 선언자의 공유가 '결제할 수 있는 지인'에게 안 닿아서다.** 공스타 부계 팔로워 다수는 결제 여력 없는 동료 수험생이고, 민지형(직장인 본계 지인)은 소수다. 방어를 문서에 반영함: §1 제1원리 명문화 · §2-3 도달 경로 3개 분리(부계/카톡 1:1/가족 pledge) · FR-S4(카톡 직접 공유 경로) · §2-4 "방문은 있는데 결제가 없음" 용의자 ①에 정확히 이 시나리오를 배치하고 처방(경로 B·C 강화)을 못박음. 차유력 = 결제 기능 오류/마찰 — §2-4 마지막 행에서 카피 A/B보다 build 에스컬레이션을 우선하게 순서 고정.

**Q2. "10건이라는 목표 자체가 틀렸다면?"** — 10건은 P1 게이트(선언자 40~60)×1회경험률 30%=12~18명의 하한 보수값으로, P2 게이트와 산술 정합(§2-1). 선언자가 40명 미만인 채 오픈하면 10건은 구조적으로 불가 — 그래서 SW0에 선언자 재고 확인을 첫 액션으로 박았다. 목표 미달 시 처방은 '더 세게 팔기'가 아니라 상류 재고 채우기다.

**Q3 (레드팀 — 회의적 응원자 민지의 공격). "이거 그냥 기프티콘보다 불편한 송금 아니야? 내 돈이 수수료 떼이고 가는 거잖아."** — 정면 반박하지 않고 구조로 답한다: 기프티콘의 진짜 비용은 수수료가 아니라 **답례 의무·어색함**(민지 실경험 P3-02)이고, 우리는 그걸 제거하는 게 상품이다(P3-01·C4). 수수료는 숨기지 않고 선공개(S1 수수료 서사·DM §3-3 원칙 승계)가 유일한 방어 — 그래서 ⛔ 회수 1(수수료율)이 오픈 공지의 선결 조건이다.

**Q4. "금지선 지켰나 — 0번 게이트 포함."** — 스킬: hook-angle-lab 실호출로 C 계열을 후킹 패밀리(self-diagnosis·comparison·reversal 등) 비교 생성. 벤치마크: WebSearch 4회 실조사(BMC·Ko-fi·GoFundMe·카카오선물). 신규 카피 전수 금지어 육안+grep 대조 — '한턱'(C7)은 금지어표에 없으나 톤 실측 대상으로 risk 中 표기. FR·C 계열의 면 태그 전수 확인: 주인공 면 카피(FR-S1~S4)에 돈 단어 0.
