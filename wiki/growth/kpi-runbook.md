## 0. 운영 규칙 (3줄)

1. **매주 일요일** 계기판 5칸 + 선행지표 3칸을 §5 로그에 1행 append. 값을 못 구하면 빈칸이 아니라 `미측정(사유)`로 기록.
2. 판독은 초록/노랑/빨강 3색. **빨강 = 하위모델이 방향을 바꾸는 신호가 아니라 "정해진 액션 실행 + 기록 + (kill 관련이면) 회장 소집" 신호다.**
3. GA4 이벤트명은 [docs/architecture.md](../../docs/architecture.md) §6에 정의된 자리(`goal_created`·`cheer_started`·`payment_success`·`wordmap_shared`·`cashout_requested`) 기준. **구현 대조 전이면 값 기록 시 `(구현 미대조)` 병기** — 이벤트가 실제 안 심겨 있으면 측정 자체가 허수다.

## 2. 계기판 5칸 — 정의·산식·출처·액션

### 2-1. 유입
- **정의**: 주간 신규+재방문 유니크 방문자(웹).
- **산식**: GA4 `Active users`(주간) — 보조로 `first_visit`(신규만).
- **출처**: GA4 표준 이벤트(자동 수집 — 커스텀 불필요). 채널 분해는 UTM(`utm_source=instagram|threads|dm`) — UTM 규약은 [dm-outbound-playbook](dm-outbound-playbook.md)·[channel-identity-kit](../brand/channel-identity-kit.md) 참조.
- **임계**: §1 표. [실험] 기본값 근거: DM 100/일×주5=500발송×응답률 8%=40 + 공스타/스레드 오가닉 — P1 기준 400이면 채널이 최소 작동.
- **빨강 액션**: ① 채널별 분해(UTM)로 어느 유입원이 죽었는지 특정 ② DM 응답률(§3-1)과 교차 판독 ③ 콘텐츠 발행 무결점 여부 확인(캘린더 대조) ④ 2주 연속 빨강 → 회장 보고(채널 믹스 재검토는 회장 회수).

### 2-2. 가입·선언 전환율
- **정의**: 유입 중 선언(목표 생성)까지 간 비율. 해낼게의 "가입"은 계정 생성이 아니라 **선언 완료**가 활성화 기준(write-first 온보딩).
- **산식**: 분자 = 주간 `goal_created` 수행 유니크 유저 / 분모 = 주간 유니크 방문(①).
- **출처**: `goal_created`(architecture.md 정의 이벤트). 카카오 OAuth 완료 시점 이벤트는 미정의 — [실험] 제안: `sign_up`(GA4 권장 이벤트명) 추가 심기. 추가 전까지는 goal_created 단일 기준으로 운영(멈추지 말 것).
- **임계**: §1 표. [실험] 기본값 근거: 콜드 랜딩→활성화 4~10% 통상 범위 (unsourced — 4주 실측 후 재캘리브레이션 1순위).
- **빨강 액션**: ① 유입의 질 문제인지(채널 분해) 퍼널 문제인지(랜딩→선언 단계별 이탈) 분리 ② 선언 페이지 카피를 [voice-copy-bank](../brand/voice-copy-bank.md) 변형으로 1개 A/B ③ 가격·플로우·기능 변경은 회장 회수.

### 2-3. 유료응원 1회경험률 (P2부터 측정)
- **정의 [stable-제안]**: **활성 선언자 중 유료 응원(클로버)을 1건 이상 받아본 비율.** — 선언자(공급) 기준.
  - ⛔ 회수 필요: 이 정의는 "응원자 중 1회 결제 전환율"로도 읽힐 수 있다. 선언자 기준 채택 근거 = P1 게이트 "선언자 40~60명"×30% = 첫 결제 12~18명으로 산술이 이어지고, kill #2("응원이 돈으로 안 흐름")의 관찰 단위가 목표 페이지이기 때문. **회장 추인 전까지 이 정의를 기본값으로 운영**(멈추지 않음), 추인되면 [stable] 승격 + decisions.md D-NNN 기록.
- **산식**: 분자 = 결제 오픈 이후 `payment_success`가 1건 이상 연결된 목표의 선언자 수 / 분모 = 결제 오픈 이후 활성 선언자 수(공개 목표 보유 + 4주 내 활동).
- **출처**: `payment_success`(architecture.md) + DB `cheer`/`goal` 조인(GA4만으로 선언자 단위 집계 불가 — Supabase 쿼리 병행).
- **임계**: §1 표(P2 게이트 ≥30% = brand-marketing-strategy §5). 보조 앵커: 건당 평균 결제액 ~5,000원(±40% 이탈 시 노랑 — 앵커 붕괴 신호).
- **빨강 액션**: ① 응원자 면 결제 마찰 점검(비로그인 결제 실동작, 1-2탭) ② 응원자 면 카피(P3 필러 "조용히 두고 가는 마음") 변형 A/B ③ 선언 카드→목표 페이지 도달률(§3-2) 교차 판독 ④ <20% 2주 지속 → **kill #2 소집 조건**(§4).

### 2-4. 반복후원율 (P2부터)
- **정의**: 결제해 본 응원자 중 같은 달(또는 30일 창) 2회 이상 결제한 비율.
- **산식**: 분자 = 30일 창 내 `payment_success` 2회+ 응원자 / 분모 = 동일 창 1회+ 응원자.
- **출처**: DB 결제 레코드(응원자 식별 기준 — 비로그인 결제 존재 시 결제수단/식별자 기준, 구현 대조 필요). GA4 단독 불가.
- **임계**: §1 표. [실험] 기본값 근거: 후원형 플랫폼 반복률 벤치마크 부재 상태의 보수적 시작값 (unsourced — 실측 재캘리브레이션 대상).
- **빨강 액션**: ① 마일스톤 pledge(고객단가 높은 준호형) 노출 강화 ② 응원 받은 주인공의 인증 업데이트 빈도와 교차(주인공이 조용하면 재후원 계기가 없음) ③ 임계 미달 지속 → kill #2 소집.

### 2-5. W4 잔존 (주인공 코호트)
- **정의**: 가입(=첫 선언) 후 4주차(22~28일)에 활동(세션 or 인증 업로드 or 목표 업데이트)한 주인공 비율. 코호트별 고정 측정.
- **산식**: 분자 = 해당 주 가입 코호트 중 W4 활동 유저 / 분모 = 해당 주 가입 코호트 전체.
- **출처**: GA4 코호트 탐색(Retention) + DB 활동 로그 교차. 첫 판독 가능 시점 = W3 코호트 기준 **W7**.
- **임계**: §1 표. 빨강 <20% = **kill #1 그 자체**([bm.md §6](../../docs/bm.md)).
- **빨강 액션**: ① 코호트 분해(DM 유입 vs 오가닉 — 시드의 질 문제인지 제품 문제인지) ② 응원 수신 경험 유무로 분해(응원 받은 주인공 vs 0명 주인공 잔존 비교 — 루프 가설 검증) ③ 즉시 회장 소집(§4). 기능 추가·피벗 논의는 하위모델 권한 밖.

## 3. 채널 선행지표 (동일 포맷)

### 3-1. DM 응답률
- **정의**: 발송 DM 중 유의미 반응(회신·질문·링크 클릭 후 방문) 비율. 절차·문구·리스트 기준 = [dm-outbound-playbook.md](dm-outbound-playbook.md) (정본 그쪽 — 여기선 판독만).
- **산식**: 분자 = 주간 유의미 반응 / 분모 = 주간 발송 수.
- **출처**: 수기 스프레드시트(인스타 DM은 API 집계 불가) + 링크 클릭은 UTM `utm_source=dm`.
- **임계**: 초록 ≥8%(D-001 게이트, [stable]) / 노랑 5~7.9% / 빨강 <5%.
- **빨강 액션**: **즉시 발송량 50% 감속 + 48h 휴지**(밴-신호 브레이크, 캘린더 §1) → 첫 줄 개인화 품질 재작성 → 리스트 타깃 재선별. 발송 재개는 소량(10/일) 테스트로.

### 3-2. 선언카드 공유율
- **정의**: 신규 선언자 중 선언 카드(또는 목표 링크)를 외부 공유한 비율. P1 게이트 ≥50%.
- **산식**: 분자 = 공유 행위 1회+ 신규 선언자 / 분모 = 주간 신규 선언자.
- **출처**: DB `share_event`(architecture.md 실재 테이블) 기준. GA4는 `wordmap_shared`만 정의돼 있음 — [실험] 제안: 선언카드 공유용 `goal_shared` 이벤트 추가. 추가 전엔 share_event 테이블 쿼리로 운영.
- **임계**: 초록 ≥50% / 노랑 30~49.9% / 빨강 <30%. [실험]
- **빨강 액션**: ① 카드 디자인·문구 점검(주인공 면 돈 언어 0 위반이 공유 사망 1순위 용의자 — "쟤 돈 걷네" 역화) ② 공유 타이밍 UX(선언 직후 vs 나중) 관찰 ③ 카드 템플릿 변형은 [visual-guidelines](../brand/visual-guidelines.md) 규격 내에서 하위모델 재량.

### 3-3. 프로필 링크 클릭률
- **정의**: 공스타/스레드 프로필의 링크 클릭 수(주간 절대수로 시작 — 노출 분모가 플랫폼마다 불안정).
- **산식**: 주간 클릭 절대수 (보조: 클릭/프로필 방문 비율 — 인스타 인사이트 제공 시).
- **출처**: 인스타/스레드 네이티브 인사이트 + GA4 UTM(`utm_source=instagram&utm_medium=bio`) 교차.
- **임계**: [실험] 초록 ≥100/주 · 노랑 40~99 · 빨강 <40. 판정 게이트: 팔로워 500 돌파 시 비율 기준으로 전환.
- **빨강 액션**: 바이오 카피 변형([channel-identity-kit](../brand/channel-identity-kit.md) 규격 내) · 콘텐츠→프로필 유도 CTA 점검.

## 4. kill-criteria 소집 (bm.md §6 — 3개 전부 회장 참석 필수)

**소집 조건** (하나라도 충족 시 하위모델은 48h 내 회의 자료 준비 + 회장 소집 요청. 자가 판정·자가 피벗 금지):
1. **kill #1**: 측정 가능한 첫 코호트부터 W4 잔존 <20%가 2개 코호트 연속.
2. **kill #2**: P2 개시 3주 후에도 1회경험률 <20%, 또는 반복후원율 <10%가 2주 연속.
3. **kill #3**: 실환전 발생 후 실측 take가 all-in 6.3% 천장에 깔려 건당 순익 구조가 성립 불가 판정, 또는 유료 CAC 없이 유입이 성립 안 함(자가확산 계수 <0.2 [실험]).

**회의 안건 템플릿** (자료는 이 포맷으로 준비):
```
1. 소집 트리거: kill #N — 실측값 vs 임계 (측정 산식·기간·코호트 명시)
2. 데이터 패킷: 계기판 5칸 전 주차 추이 + 선행지표 3칸 + 코호트 분해
3. 반증 검토: 측정 오류 가능성 / 특이 주차(시즌·장애) / 분해 시 살아있는 세그먼트
4. 옵션 3안: (a) 계속+가설수정 (b) pivot 방향 (c) kill — 각각 근거·비용
5. 회장 결정 → decisions.md D-NNN append
```
