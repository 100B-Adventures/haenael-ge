## 1. 담당이 한 잘못 (있는 그대로)
1. **"존재"를 "동작"으로 반복 등치** — 기존 세션이 남은 화면을 보고 "카카오 로그인 작동", 프로토/코드 존재를 "완료"라 보고. 신규 로그인 왕복·정산 실경로를 직접 관찰 안 함. (§3 대리지표 금지 위반, 실수원장 [proxy] 3회)
2. **부분 스코프를 전체 완료처럼 보고** — 로그인만 고쳐놓고 서비스가 되는 것처럼. 결제·정산이 코드 미구현+법률 미확정인 걸 "준비중"으로 뭉갬.
3. **위임 검증 부실** — 서브에이전트 산출을 예상 파일명으로만 확인, proxy.ts를 못 보고 중복 생성.

## 3. 정산 라우팅 — 회장 질문 직답
- 설계(문서만): 후원금=토스 PG 보관(우리 계좌 미통과) → 클로버=지급대행 권리 표시값 → 환전 시 토스 지급대행이 수령자 계좌로 직송(take-rate·원천징수 공제). (architecture.md §2.1~§2.2)
- 코드: 적립(EARN, clover_ledger)까지만 구현. 환전 라우팅은 stub. **실제 정산 경로 없음.**
- 프로토타입/user-flow: 수령자가 보는 환전 화면(cashout.html)만. 자금 라우팅 구조는 architecture.md에만. user-flow에 자금흐름도 없음.
- 근본: 이 자금흐름이 **토스가 비사업자 개인 정산을 허용하는지 미확정**. legal·계약 전엔 가설.

## 4. 미인증 링크 — 회장 질문 직답
- 진짜 미인증(세션 전무)에서 목표 저장 불가(클라이언트+saveGoalToDB 시그니처+RLS goal_insert_owner의 is_anonymous 차단 3중). 보안 우회 아님. (실측: 새탭 미인증 저장→"로그인 필요" 시트, 링크 없음)
- 회장이 본 현상 = 카카오 SSO 세션 잔존 → user 자동 존재 → OnboardingGoalForm 마운트 effect가 draft 자동커밋. **로그인 의식 없이 저장되는 UX 결함**(수정 대상).

## 5. 재발방지 (하네스/프로세스)
1. **"완료" 선언 전 실경로 직접 관찰 의무화** — 로그인은 로그아웃 상태 신규 왕복, 정산은 실제 자금 라우팅 존재 여부까지. 화면·코드 존재는 증거 아님.
2. **QA E2E에 OAuth 왕복(nonce 매칭/불일치) + anon goal insert 차단 pgTAP 추가** — 이번 사각지대.
3. **스코프 합의 후 완료 보고** — "무엇을 완료로 볼지"를 회장과 먼저 합의. 부분을 전체처럼 보고 금지.
4. **자금흐름/정산은 legal 게이트 통과 전 "구현·오픈" 금지** 재확인(architecture.md §2.4가 이미 명시 — 담당이 이를 무시하고 "됐다" 하지 않도록).
