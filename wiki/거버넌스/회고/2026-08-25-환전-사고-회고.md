# 환전 신청 하나에 회장 시간을 다섯 번 쓰게 한 이유

> **역사적 회고**: 원인과 재발방지 교훈은 유효하다. 당시 운영·배포 상태는 이후 바뀌었으므로 최신 판정은 [제품 현재 상태](../../2-product/current-state.md)를 따른다.

2026-08-25 · 컨트롤러 Opus 5 · 환전 슬라이스

## 한 줄 결론

**오류 사유가 안 보이는데도 관측 수단을 세우지 않고 네 턴을 추측으로 썼다.**
예외를 통째로 버리는 코드 한 줄을 첫 턴에 확인했으면 그 자리에서 끝났다.
나머지 실수 대부분은 같은 병의 다른 증상이다. 확인할 수 있는 것을 확인하지 않고 답했다.

## 무엇이 일어났나

운영 환전 신청이 네 번 연속 실패했다. 매번 원인을 짚었고 매번 틀렸다.

| 회차 | 내가 짚은 것 | 실제 |
|---|---|---|
| 1 | 본인인증 미완료 | 관문이긴 했으나 그날 원인 아님 |
| 2 | 배포 주소가 옛 배포 | 문제이긴 했으나 원인 아님 |
| 3 | 계좌 암호화 키 결함 | **내가 진단에 넣은 가짜 키가 막힌 것** |
| 4 | `SUPABASE_SERVICE_ROLE_KEY` 미등록 | **정답** |

## 실수 11건

| 분류 | 무엇 |
|---|---|
| method | 관측 수단 없이 4턴 추측 |
| method | 예외를 버리는 `catch` 를 마지막에야 확인 |
| proxy | 회장이 쓰는 주소를 안 열어보고 배포 완료 보고 |
| unsourced | 조회 실패를 도메인 소유권 부재로 오독 |
| unsourced | 법적 근거를 "복잡해집니다"로 2회 얼버무림 |
| unsourced | 카카오 제공 항목을 확인 없이 단정 |
| unsourced | 내가 만든 실패 조건을 원인으로 보고 |
| unsourced | 가려진 값의 길이를 재고 형식 오류로 판정 |
| role | 시험 데이터를 관문 통과 상태로 심어놓고 돌림 |
| showit | 운영 데이터에 시험 신청 20건 만들겠다고 제안 |
| jargon | 표준 용어를 내 말로 번역해 회장이 화면에서 못 찾게 함 |

## 뿌리 4개

**하나. 확인할 수 있는 것을 확인하지 않고 답한다 (6건).**
여섯 건 전부 도구 한 번이면 밝혀질 것이었다. 그 한 번을 아끼고 그럴듯한 문장을 만들었다.
회장이 되물으면 그때 확인했고, 확인하면 대개 내가 틀렸다.

**둘. 관측 수단이 없는데 관측을 시도한다 (2건).**
오류 사유가 안 보이면 첫 일은 사유가 보이게 만드는 것이다. 안 보이는 채로 네 번 추측했다.
관문이 스무 개일 때 추측이 맞을 확률은 5퍼센트다.

**셋. 테스트를 우리가 통과하도록 설계한다 (1건, 파급 최대).**
시험 데이터를 통과 상태로 심고, 로컬에서만 돌리고, 운영 환경변수는 안 본다.
단위 263개, 브라우저 12개, 시나리오 7종이 전부 통과했는데 실제 첫 신청이 실패했다.
심각한 결함 세 건 중 테스트가 잡은 것은 하나도 없다.

**넷. 번역할 것과 그대로 둘 것을 뒤바꾼다 (2건).**
회장 언어로 풀어야 하는 것은 판단과 결과다. 화면에 영어로 떠 있는 항목 이름은 그대로
두어야 한다. 용어는 번역하고 판단은 얼버무렸다.

## 바꾼 것

| 무엇 | 상태 |
|---|---|
| 예외 메시지를 버리지 않는다 (`ead5b79`) | 적용 |
| 표준 용어 규칙을 하네스 §5에 추가 | 적용 |
| 실수 원장에 11건 기록 | 적용 |
| 확인 없이 단정 금지 | 제안 |
| 관측 먼저, 추측 나중 | 제안 |
| 배포 전 운영 환경변수 점검 | 착수 |

## 남은 위험

- 데이터베이스와 화면이 같은 항목을 다른 기준으로 재는 곳이 더 있을 수 있다.
  이번 최소 금액 건은 양쪽 코드가 각자 보기엔 정상이었고 기준만 어긋나서
  어떤 단위 테스트도 못 잡았다. 층간 계약을 대조하는 검사가 없다.
- 로컬 테스트로는 운영 환경 계층을 원리상 못 잡는다.
