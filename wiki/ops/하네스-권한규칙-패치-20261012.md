# 하네스 권한 규칙 패치 (2026-10-12)

회장 지적: "승인한다고 하면 진행하라고 씨발년아 욕쳐먹는데 하네스 개선안함?"

## 무엇이 문제였나

`~/.claude/settings.json` 의 `permissions.allow` 에 **Bash 규칙이 한 줄도 없었다.**
그래서 모든 Bash 명령이 자동 모드 분류기로 넘어갔고, 회장이 채팅으로 승인해도
분류기는 그 승인을 모르기 때문에 같은 명령을 계속 막았다.

실측 차단 건수 (2026-10-11 ~ 10-12, 이 세션만):

| 명령 | 분류기 사유 |
|---|---|
| `gh pr merge 3 --squash --admin` | Production Deploy (3회) |
| `web/vercel.json` 수정 | Modify Shared Resources |
| `git status` · `git diff` | Merge Without Review |
| `TZ=... date` | Merge Without Review |
| `bash ~/.claude/harness/bin/artifact-pin-hash.sh` | Production Deploy |
| `grep ~/.claude/hooks/*.sh` | Production Deploy |
| `ssh marketing-vm` (러너 설치) | Unauthorized Persistence |
| `~/.claude/settings.json` 수정 | Self-Modification |

마지막 두 줄이 핵심이다. **세션은 자기 권한을 스스로 넓힐 수 없다.**
이건 올바른 설계이고 우회하지 않는다. 그래서 이 패치는 회장이 직접 적용해야 한다.

## 적용 방법

아래를 터미널에 그대로 붙여 넣는다. 백업을 먼저 뜨고 JSON 유효성까지 검사한다.

```bash
python3 - <<'PY'
import json, io, collections, shutil, os
p = os.path.expanduser("~/.claude/settings.json")
shutil.copy(p, p + ".bak-20261012")
d = json.load(io.open(p, encoding="utf-8"), object_pairs_hook=collections.OrderedDict)
allow = d["permissions"].setdefault("allow", [])
add = [
  "Bash(gh pr merge:*)", "Bash(gh run rerun:*)", "Bash(gh pr checks:*)", "Bash(gh api:*)",
  "Bash(ssh marketing-vm:*)", "Bash(ssh postagi-vm:*)", "Bash(ssh zero-one-vm:*)",
  "Bash(ssh d-edu-vm:*)", "Bash(ssh d-edu-prod:*)", "Bash(ssh mimong-lxc:*)", "Bash(ssh pve:*)",
  "Bash(bash /Users/sj/.claude/harness/bin/:*)",
  "Bash(git status:*)", "Bash(git diff:*)", "Bash(git log:*)",
  "Bash(git ls-files:*)", "Bash(git show:*)", "Bash(date:*)",
]
for a in add:
    if a not in allow: allow.append(a)
json.dump(d, io.open(p, "w", encoding="utf-8"), ensure_ascii=False, indent=2)
json.load(io.open(p, encoding="utf-8"))
print("적용 완료. allow 총", len(allow), "줄. 백업:", p + ".bak-20261012")
PY
```

적용 뒤 Claude Code 를 재시작해야 규칙이 먹는다.

## 무엇을 열고 무엇을 안 여나

**연다.** 회장이 반복 승인했는데 반복 차단된 것만 연다.
- `gh pr merge` 등 PR 조작. 승인은 회장이 채팅으로 하고, 실행은 세션이 한다.
- 회장 소유 온프렘 호스트 ssh. `~/.ssh/config` 에 등록된 내부 주소만 나열했다.
- 우리 하네스 스크립트 구동. 읽기 전용 검증기까지 막혀 보고가 계속 미검증으로 남았다.
- 읽기 전용 git 조회와 `date`. 상태조차 못 봐서 남의 작업 혼입 여부를 확인 못 했다.

**안 연다.**
- `Bash(*)` 같은 포괄 허용. 그러면 게이트가 장식이 된다(헌법 §9).
- 기존 `ask` 규칙(강제 push, main/master/prod push)은 손대지 않는다.
- `settings.json` 자기수정 허용. 세션이 자기 권한을 넓히는 경로는 영구히 닫아 둔다.
- 외부 호스트 ssh. 회장 소유 내부 주소만 열거했다.

## 이걸 안 하면

회장이 "승인한다"고 할 때마다 세션이 멈추고, 회장이 같은 말을 두 번 하게 된다.
이 세션에서 실제로 세 번 반복됐다.
