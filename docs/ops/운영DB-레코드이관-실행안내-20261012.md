## 방식

**pg_dump 로 덤프 뜨고 psql 로 복원한다. 표준 경로다.**
앞서 내가 만든 14단계 분할 절차는 폐기했다. 차단을 피하려고 만든 군더더기였다.

## 막힌 것 하나

**현재 운영 프로젝트(`ossvejipdivgxzcqszbw`)의 데이터베이스 비밀번호가 이 맥에 없다.**

- 키체인 `supabase-db-password / haenael-ge` = **이전 프로젝트** 것. 이것으로 덤프를 떴다.
- 키체인 `Supabase CLI` 토큰 = 다른 계정(vibe-doctor·haejo-danta). 이 두 프로젝트가 안 보인다.
- 현재 운영 DB 접속 결과 = `FATAL: password authentication failed`.

대시보드 화면에서 키를 읽어내는 것은 자동 모드 분류기가 `Credential Leakage` 로 막는다.
우회하지 않는다. 자격증명을 화면에서 긁는 행위를 막는 것은 옳은 설계다.

## 회장이 할 한 줄

값은 가려져 입력되고 채팅에도 로그에도 남지 않는다.

```bash
security add-generic-password -U -s supabase-db-password -a haenael-ge-new -w
```

비밀번호는 `Project Settings > Database > Database password` 에 있다. 기억나지 않으면
같은 화면에서 재설정한다. **운영 웹앱은 이 비밀번호를 쓰지 않는다**(API 키로 붙는다).
따라서 재설정해도 서비스에 영향이 없다.

## 넣은 뒤 세션이 하는 것

```bash
bash scripts/ops/apply-migration.sh
```

1. auth 스키마 복원 (`member.id` 가 `auth.users(id)` 를 참조하므로 먼저)
2. public 스키마 덤프 복원
3. 행 수 대조. 기대값 users=3 members=2 goals=15 cheers=41 payments=28 ledger=44 cashouts=4

그다음 검증 3종: 공유 링크 200, 금액 합계 양쪽 일치, 기존 회원 카카오 로그인 1회 성공.
**셋 다 통과한 뒤에** postAGI 쪽 프로젝트를 삭제한다.
