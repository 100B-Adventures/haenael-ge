# 카카오 로그인 실패 원인 확정 (2026-10-12)

회장 질문: "카카오 로그인 왜 안돼"

## 결론

**엣지 함수 `auth-kakao` 의 카카오 자격증명이 틀렸다.** 코드 문제도, 이관 문제도 아니다.

## 실측

| 확인 | 결과 |
|---|---|
| `/auth/kakao/start` | 307, 카카오 인증 주소로 정상 이동 |
| 카카오 로그인 화면 | 200 정상 표시 (client_id 를 카카오가 받아들임) |
| 엣지 함수 `auth-kakao` 호출 | 502 `kakao_error` |
| 카카오가 준 오류 | `KOE010 invalid_client, Bad client credentials` |

## 어느 값이 틀렸나 (대조 실험)

같은 카카오 토큰 발급 주소에 두 번 호출해 갈랐다.

| 호출 | 카카오 응답 | 해석 |
|---|---|---|
| 로컬 REST 키 + **로컬 client_secret** | `KOE320 authorization code not found` | **자격증명은 정상.** 코드만 가짜라 거부 |
| 로컬 REST 키 + **secret 없음** | `KOE010 Bad client credentials` | 엣지 함수가 내는 오류와 동일 |

**즉 로컬 키체인의 값이 맞는 값이고, 엣지 함수에 들어 있는 값이 틀렸다.**

대시보드 확인 결과 `KAKAO_CLIENT_ID` 와 `KAKAO_CLIENT_SECRET` 둘 다 **등록은 돼 있다.**
없어서가 아니라 값이 다른 것이다. 10-07 새 프로젝트를 만들 때 옛 값이나 다른 앱 값이 들어간 것으로 보인다.

## 고치는 법

대시보드 `Edge Functions > Secrets` 에서 두 개를 바로잡는다.

- `KAKAO_CLIENT_ID` = `c274280c95e2859cbbce3fdcc2758a9c`
  (운영 웹이 이미 쓰는 REST API 키다. 브라우저 번들에 들어가는 공개값이라 여기 적어도 된다)
- `KAKAO_CLIENT_SECRET` = 로컬 키체인 `kakao-client-secret / haenael-ge` 의 값
  (32자. 세션이 클립보드에 올려 둔다. 값은 문서·채팅에 적지 않는다)

고친 뒤 확인:

```bash
curl -sS -X POST https://ossvejipdivgxzcqszbw.supabase.co/functions/v1/auth-kakao \
  -H "Content-Type: application/json" -H "apikey: <publishable key>" \
  -d '{"code":"probe-invalid","redirect_uri":"https://haenael-ge.vercel.app/auth/kakao/callback"}'
```

`KOE010` 이 아니라 `KOE320` 이 나오면 자격증명이 맞은 것이다.
