## 3. 발견하고 고친 결함 2건

### 결함 1: 테스트 간 픽스처 오염 (테스트 코드)

증상은 5번 케이스가 성공 화면 요소를 찾지 못하고 실패한 것이다. 근본 원인은 앞선 케이스가 만든 진행 중 신청과 소진된 클로버 잔량을 같은 사용자 픽스처가 그대로 물려받아, 신청 폼 대신 "이미 처리 중인 신청이 있어요" 화면이 렌더된 것이다. 제품 결함이 아니라 테스트 격리 결함이다.

조치: 케이스별 픽스처 초기화. 어설션 삭제나 완화는 하지 않았다.

### 결함 2: 마이그레이션 타임스탬프 충돌 (배포 차단급)

신규 파일 `20260802010000_member_phone_alimtalk.sql`이 **이미 운영에 적용된** `20260802010000_cashout_security_hardening.sql`과 번호가 겹쳤다.

영향은 심각하다. 도구가 "적용 완료"로 오인해 이 마이그레이션을 영구히 건너뛴다. 그대로 배포했다면 운영에 전화번호 칸이 없는 채 코드만 올라가 환전 신청이 전량 실패했을 것이다.

조치: `20260805010000_member_phone_alimtalk.sql`로 번호를 옮겼다.

## 4. 미검증 (정직 고지)

- **pgTAP 63개 어설션**: Docker 소켓 권한 문제로 0회 실행. RLS 정책은 코드 리뷰로만 확인했다. `member_update_own`은 USING만 있고 WITH CHECK가 없는데, UPDATE에서는 USING이 그대로 적용되므로 본인 행만 수정 가능하다.
- **운영 왕복**: 실제 카카오 로그인에서 환전 신청, 관리자 지급완료까지의 경로는 미실행.
- **운영 마이그레이션 드리프트**: `20260720~20260731` 12건이 운영에 미적용인데 `20260802`, `20260803`은 적용된 순서 역전 상태가 남아 있다. 이번 작업 범위 밖이지만 별도 정리가 필요하다.
