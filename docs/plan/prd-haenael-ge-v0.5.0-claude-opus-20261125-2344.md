## ⓥ v0.4.0 → v0.5.0 변경 요약 (3줄)

1. **결과 올리기(신규)**: 목표 주인이 "해냈어요 / 이번엔 못 해냈어요"와 한마디(1~140자), 사진 0~1장을 올린다. 목표는 종료 상태가 되고 결과 화면이 열린다. 결과는 지급 조건이 아니다.
2. **응원자 결과 알림(신규 템플릿 1종)**: 결과 알림을 신청한 응원자에게 목표 1개당 1회 알림톡, 신청 안 했거나 번호가 없거나 도착 실패면 인앱. 도착은 솔라피 상태 4000 으로 확인한다.
3. **결과 화면과 재공유(신규)**: 보는 사람(주인·응원자·친구·처음 온 사람)마다 다른 결과 화면. 응원자는 "내 응원이 담긴 자리"를 보고 카카오톡 공유·인스타 스토리 이미지로 다시 퍼뜨리고, 처음 온 사람은 "나도 해낼게"로 들어온다.

### 15.0.1 욕망·결핍·돈이 나오는 순간 (standard-planning §4)

| 사람 | ①건드리는 욕망 · 채우는 결핍 | ②그 감정이 가장 커지는 순간 | ③관심→신뢰→결제에서 맡는 칸 | 이 화면이 설계하는 감정·보상 |
|---|---|---|---|---|
| **주인공 윤도경**(persona A-1) | 욕망: 새벽 6시 도서관을 버틴 걸 누가 알아줬으면. 결핍: 하트 40개는 3초 뒤 휘발되고, "해냈다"를 공스타에 올리면 자랑 같고, 응원해 준 민지에게는 "갚을게" 빚진 느낌만 남는다 | 결과(합격·점수)를 확인한 직후, 해낼게 목표 화면을 연 순간 | 공급측 잔존과 다음 선언. "해냈다"를 올린 사람이 다음 목표를 또 선언한다 | **해소 + 즉시 보상**: 결과를 '자랑'이 아니라 '응원해 준 7명에게 하는 보고'로 프레이밍해 체면 비용을 없앤다. 올리자마자 "응원자 7명에게 소식이 가고 있어요 → 6명에게 도착"으로 숫자가 차오른다 |
| **응원자 김민지**(persona B-1) | 욕망: 내 3,000원이 그 애가 해내는 데 한몫했다는 확인. 결핍: 응원하고 나면 끝이라 결과를 모른다. 생색은 싫어서 먼저 묻지도 못한다 | 카톡에 "응원하신 목표의 결과 소식"이 온 순간과 결과 화면에서 내 응원 단어를 찾은 순간 | 재응원과 바이럴. 남의 성공을 퍼뜨리는 건 체면 비용 0이고 "내가 알아본 사람"이라는 지위가 생긴다 | **기대 → 확인 보상**: 알림톡은 결과를 숨기고(호기심), 화면에서 "D-34에 보낸 민지님의 응원"과 내 단어가 워드맵에서 빛난다(내 몫의 가시화). 그다음 행동은 하나, "카톡으로 알리기" |
| **처음 본 사람**(민지의 친구) | 욕망: 나도 저렇게 해내고 싶다, 저런 응원을 받고 싶다. 결핍: 혼자 하는 목표는 아무도 몰라준다 | 카톡방에 뜬 결과 카드를 눌러 "7명의 응원으로 해냈다"를 본 순간 | 관심 → 사용. 신규 선언자 유입(공급) 또는 주인공 다음 목표 응원(수요) | **사회적 증거 + 커밋먼트**: 인원수는 크게, 금액은 없이. 1순위 버튼 "나도 해낼게" |

### 15.0.2 고유명사 문장 (positioning.md §2.1 칸 9)

- 자리: 결과 카드 제목, 카카오톡 공유 문구, 결과 화면 첫 줄.
- 후보(최종 문구는 design 단계 copy-shotgun 으로 회장이 고른다): "**해낼게로 해냈다.**" / "나 해낼게 했고, 해냈어." / "7명이 밀어줘서 해냈어."
- 뜻 한 줄: "해낼게했다" = 친구들에게 선언하고, 조용히 밀어준 친구들 덕에 끝까지 갔다.
- 기존 두 벌("우리 서로 해낼게하자" / "우리 서로 해낼게해", `docs/growth/growth-해낼게-위키정리-준비물-v0.1.1-…md` 79행)과 맞춰 한 계열로 고른다. 이 PRD는 결과 쪽 문장만 후보로 둔다.

## 15.2 용어 고정

| 용어 | 정의 | 혼동 금지 |
|---|---|---|
| **결과** | 목표 주인이 올린 결과 판정(해냈어요 / 이번엔 못 해냈어요) + 한마디 + 사진(선택). 목표 1개에 결과 1개 | 업적, 인증샷, 진행 기록 |
| **종료** | 목표 상태가 진행에서 끝남으로 바뀐 것(현행 `CLOSED`). 결과를 올리면 종료되고, 결과 없이도 종료할 수 있다 | 결과 |
| **결과 알림 신청** | 응원자가 "결과 나오면 카톡으로 받기"를 직접 누른 기록. 응원한 목표마다 따로 | 마케팅 수신 동의, 분석 동의(D-054) |
| **발송** | 솔라피 발송 API 가 요청을 받아들임(현행 코드의 `SENT`) | 도착 |
| **도착** | 솔라피 메시지 상태 4000(수신 완료). 10분 안에 조회해 확정 | 발송 |
| **인앱 대체** | 알림톡이 못 가거나 도착 실패일 때 해낼게 안 알림 목록에 같은 소식을 넣는 것(현행 `INAPP` 폴백) | 푸시 알림(서비스 워커 푸시는 별도 기능, 이번 범위 밖) |
| **응원자** | 그 목표에 확정된 응원이 1건 이상 있고 회원에게 귀속된 사람(D-057). 익명 포함 | 친구, 방문자 |
| **결과 화면** | 목표 페이지가 종료+결과 상태일 때 그려지는 화면. 보는 사람에 따라 4가지(주인·응원자·친구·처음 온 사람) | 결과 카드 |
| **결과 카드** | 결과 화면에서 만든 공유용 이미지 2종: 카카오톡 공유 미리보기(가로형)와 인스타 스토리(9:16) | 알림톡 이미지(쓰지 않는다) |

## 15.3 안 비교: 결과물 형태와 공개 범위 (안 4개 → 추천 1안)

정해진 것(못박음): 금액 비공개, 결과는 지급 조건 아님, 알림톡은 신청자에게 1회, 응원은 회원만. 그 밖은 아래에서 고른다.

| 안 | 결과물 형태 | 알림톡 | 공개 범위 | 고르면 | 안 고르면 / 단점 |
|---|---|---|---|---|---|
| **A(추천) 결과 화면 + 공유 카드** | 목표 페이지가 결과 상태로 바뀐 웹 화면(보는 사람별 4종) + 카카오톡 공유 카드 + 인스타 스토리 이미지 | 텍스트형 1종, 버튼 "결과 보기"(웹링크) | 목표의 공개범위를 그대로 따른다. 단 "이번엔 못 해냈어요"는 기본 응원자만 보기(주인이 넓힐 수 있음) | 알림톡 → 화면 → 재공유 → 신규 유입이 한 링크로 이어진다. 기존 목표 페이지·워드맵·공유 링크 자산을 재사용(카카오 공유와 링크 복사는 이미 `share_link_copied`·`wordmap_shared` 로 운영 중) | 화면 4종 상태 설계와 카톡 안 브라우저 실기기 QA 비용이 가장 크다 |
| B 카드 이미지만 | 인스타 스토리용 이미지 한 장 저장. 웹 결과 화면 없음 | 텍스트형, 버튼은 기존 목표 페이지 | 이미지에 담긴 것만 퍼진다 | 개발이 가장 작다. 공스타 사용자 습관(스토리)과 맞다(Strava, ref-04) | 이미지를 본 사람이 눌러 들어올 곳이 없어 바이럴 고리가 끊긴다. 응원자 "내 응원" 보상을 줄 자리가 없다 |
| C 알림톡 안에서 끝내기 | 이미지형·강조형 알림톡에 결과 요약, 버튼 "공유하기" | 이미지형 | 카톡 수신자만 | 사용자가 화면 이동 없이 결과를 본다 | **심사 반려 위험 높음**: 주인 사진은 개인정보 유추 가능 이미지라 발송 불가, "공유하기" 버튼은 신청 범위 밖 정보로 광고성 판정 위험(ref-05). 가변 이미지 가능 여부도 공식 문서에서 확인 못 함 |
| D 응원자 전용 소식 | 결과는 응원자에게만 보이는 화면. 외부 공유 없음(Kickstarter 후원자 전용 업데이트형) | 텍스트형 | 응원자만 | "조용히"가 가장 강하게 지켜진다. 실패 결과도 부담 없이 올린다 | 회장 원문 "전파"를 못 한다. 바이럴 0 |

## 15.5 기능 요구 (입력 / 출력)

> PRD 는 목적·입출력·경계값까지만 쓴다(standard-planning §3). 데이터 타입·API 계약·테이블은 eng-design 에서 회장과 정한다. 아래 "데이터 항목"은 무엇이 필요한지만 적는다.

### FR-R1 결과 올리기 (목표 주인)

- **입력**: 목표(본인 소유, 진행 중) · 결과 판정 2택(해냈어요 / 이번엔 못 해냈어요) · 한마디 1~140자(필수, 공백만 불가) · 사진 0~1장(jpg·png·heic·webp, 10MB 이하) · 응원자에게 알리기(기본 켬) · 실패일 때만 "공개 범위대로 보이기"(기본 끔).
- **출력**: 목표가 종료 상태가 되고 결과가 붙는다. 주인 화면에 결과 카드 미리보기와 "응원자 N명에게 소식이 가고 있어요". 사진은 검수 대기로 들어가고(목표 커버 검수 경로 재사용) 승인 전에는 주인에게만 보인다.
- **진입점**: 목표 화면의 1순위 관리 행동이 "결과 올리기"가 된다. 기존 "종료"는 "결과 없이 끝내기"(보조)로 남고 지금 확인창 문구를 유지한다.
- **데이터 항목**: 결과 판정, 한마디, 사진 자산 참조, 게시 시각, 알림 여부, 실패 결과 공개 확장 여부.
- 근거: 회장 원문 "응원 결과를 올리고", GoFundMe 사진+한마디 업데이트(ref-02), 현행 `close_my_goal`(20261025010000 마이그레이션 1508행)·`GoalManagementActions.tsx` 확인창.

### FR-R2 결과 알림 신청 (응원자)

- **입력**: 응원 결제 완료 화면에서 "결과 나오면 카톡으로 받기" 한 번 누름. 이미 응원한 목표는 "내가 응원한 목표" 목록 행에서도 신청할 수 있다.
- **출력**: 버튼이 "결과 나오면 알려 드릴게요"로 바뀐다. 마이페이지 응원 목록 행에 종 표시. 언제든 끌 수 있다.
- **이유**: 카카오 심사 가이드는 요청에 따른 정보로 인정받으려면 본문에 신청 사실을 적고 1회 신청에 1회 발송하라고 한다(ref-05, 캡처에서 원문 관찰됨). 결제는 응원이지 결과 알림 신청이 아니므로 별도 신청이 있어야 템플릿 고정 문장 "신청하신"이 사실이 된다. 08-12 응원 도착 템플릿이 "수신자가 요청했음이 확인 가능한 문구"가 없어 반려된 이력이 있다(`docs/_archive/archive/session-state/session-state.core.until-2026-08-30.md` 2085~2135행).
- **배치 근거**: 결제 완료 화면은 응원자의 감정이 가장 높고 "다음 행동 1개" 자리다(DESIGN §6, D-051 결제 성공 화면). 결제 완료 화면 시안을 바꾸므로 design 단계 델타 시안 대상이다.

### FR-R3 응원자 결과 알림 발송

- **입력**: FR-R1 게시 이벤트(알리기 켬).
- **대상 산출**: 그 목표에 확정 응원이 있고 회원에게 귀속된 사람(익명 포함) 중 탈퇴·차단 관계·주인 본인 제외. **사람 기준 1회**(한 사람이 3번 응원해도 1통).
- **채널 판정**(사람마다): 결과 알림 신청 + 전화번호 있음 + 템플릿 승인·설정됨 → 알림톡. 그 밖 → 인앱. 알림톡이 발송 실패거나 10분 안에 도착(4000)이 안 되면 인앱 대체.
- **출력(응원자)**: 알림톡 또는 인앱 알림 1건. **출력(주인)**: "N명에게 갔어요 · 카톡 도착 M · 앱 알림 K".
- **안전 장치**: 같은 목표에 두 번째 발송 금지(결과 수정·삭제·재게시도 재발송 없음). 스테이징은 허용 번호 목록 밖으로 알림톡을 보내지 않는다. 발송 기능은 서버 설정 스위치를 두되, §15.10 실기기 QA 행이 전부 PASS 되기 전에는 운영에서 켜지 않는다(11-25 결제 ON 사고의 같은 구조를 막는다).
- 근거: 회장 원문 "응원한 사람들에게는 알림톡 전달", 현행 notify 의 INAPP 폴백(`supabase/functions/notify/index.ts`), D-057 귀속, 카카오 1회 원칙(ref-05).

### FR-R4 결과 화면 (보는 사람별)

| 보는 사람 | 반드시 보이는 것 | 절대 안 보이는 것 | 1순위 버튼 |
|---|---|---|---|
| 주인 | 결과·한마디·사진(검수 중이면 "확인 중"), 응원자 수, 워드맵, 알림 도착 현황, 응원자 이름(익명 제외) | 응원별 금액 | 카톡으로 알리기 |
| 응원자(로그인) | 위 공개 요소 + **"내 응원" 블록**: 내가 응원한 날("D-34"), 내가 남긴 단어(워드맵에서 강조), 익명이었으면 "익명으로 보낸 내 응원" | 다른 응원자 금액, 내 금액 이외 | 카톡으로 알리기 |
| 친구(로그인, 응원 안 함) | 결과·한마디·사진(승인 후)·응원자 수·워드맵 | 응원자 이름, 금액 | 다음 목표 소식 받기 |
| 처음 온 사람(비로그인 포함) | 결과·한마디·사진(승인 후)·"N명의 응원으로" | 응원자 이름, 금액, 응원자 얼굴 | **나도 해낼게** |

- **카톡 안 브라우저 로그인**: 응원자가 알림톡에서 들어와 로그인이 안 돼 있으면 공개 요소를 먼저 그리고 "내 응원 보려면 카카오로 로그인" 한 줄을 둔다. 로그인 뒤 **같은 결과 화면으로 돌아온다**(D-057 의 복귀 규칙과 같은 방식). 이 경로가 11-25 이다솔 사례의 실패 지점이라 AC 와 실기기 QA 에 별도 행을 둔다.
- **화면 성능**: 카톡 안 브라우저(iOS·Android) 4G 기준 결과 화면 LCP 3초 이하. 미달이면 현재 실측값을 기록하고 기능 항목은 닫는다(work_first_rule).
- 근거: D-003, D-050(손님 응원 상세는 받은 사람 마이페이지에서만), D-057, 승인 시안 목표 페이지 구조(design 단계에서 델타).

### FR-R5 재공유

- **입력**: 결과 화면의 공유 버튼.
- **출력 3종**: ①카카오톡 공유(피드: 결과 카드 이미지 · 고유명사 문장 · "결과 보기" 버튼) ②링크 복사 ③인스타 스토리용 9:16 이미지 저장(사진 + 결과 + "N명의 응원으로" + 해낼게 표기, 금액·응원자 이름 없음).
- **규칙**: 공유 링크에는 유입 출처 표시(결과 화면 경유)를 붙여 FR-R6 귀착에 쓴다. 사진이 검수 전이면 카드에는 사진 대신 목표 커버(또는 기본 그림)를 쓴다.
- 근거: 카카오톡 공유는 웹에서 JavaScript SDK 로만 된다(ref-06), Strava 스티커가 숨긴 수치를 빼는 규칙(ref-04), 현행 `wordmap_shared`·`share_link_copied` 이벤트.

### FR-R6 바이럴 귀착과 다음 행동

- **처음 온 사람**: "나도 해낼게" → 카카오 로그인 → 목표 만들기(현행 흐름) / 주인공에게 진행 중인 다른 목표가 있으면 "지금 도전 중인 목표 응원하기"(보조).
- **응원자·친구**: "다음 목표 소식 받기" → 주인공이 다음 목표를 선언하면 **인앱 알림** 1회. 이 알림은 알림톡으로 보내지 않는다(새 목표 소식은 응원자가 신청한 결과 알림의 범위 밖이고 응원 결제를 부르는 성격이라 광고성 판정 위험).
- **귀착**: 결과 화면 경유로 시작된 가입·목표 선언·응원 결제를 결과 1건 단위로 센다(북극성 지표).
- 근거: BRAIN ⑤추천(사회적 증거), 카카오 가이드 "다른 재화나 서비스 홍보가 포함되면 광고성"(ref-05 캡처).

### FR-R7 도착 확인

- **입력**: 알림톡 발송 결과의 메시지 ID.
- **출력**: 10분 안에 솔라피 메시지 조회로 최종 상태를 받아 기록한다. 4000 = 도착, 그 밖 = 실패 사유 코드와 함께 인앱 대체. 주인 화면의 도착 수는 이 값을 쓴다.
- **범위**: 결과 알림은 필수. 기존 3종(응원 도착·환전 신청·환전 지급)에도 같은 조회를 붙이는 것을 권장한다. 현행 코드는 발송 API 200 을 `SENT` 로 끝내고 도착을 확인하지 않는다(`supabase/functions/_shared/alimtalk.ts` 99~102행). 회장 질문 "알림톡 잘 전달되었는지도 체크하고 있냐?"에 대한 제품 쪽 답이 이 FR 이다.
- **방식**(조회 주기·웹훅 여부)은 eng-design 에서 정한다.
- 근거: 솔라피 상태 코드 4000 = 수신 완료, `GET /messages/v4/list`(ref-07).

### FR-R8 기한 지남 넛지 (주인)

- **입력**: 목표 기한이 지났고 진행 중이며 결과가 없음.
- **출력**: 주인에게 **인앱만** D+1, D+7 두 번 "결과를 올리면 응원자 N명에게 소식이 가요". 자동 종료하지 않는다. 기한 없는 목표에는 보내지 않는다.
- **알림톡을 안 쓰는 이유**: 주인에게 결과 올리기를 재촉하는 알림톡은 주인이 신청한 정보가 아니라 새 템플릿·심사가 하나 더 필요하고 광고성 위험이 있다. 1차는 인앱으로 효과를 보고 판단한다.

### FR-R9 결과 수정·삭제

- 한마디·사진은 게시 뒤에도 고칠 수 있다(화면에는 최신본, "수정됨" 표시). 결과 판정(해냈어요/못 해냈어요)은 바꿀 수 없다. 바꾸고 싶으면 결과를 내리고 새 목표로 다시 선언한다.
- 결과를 내리면 결과 화면은 "주인이 결과를 내렸어요"가 되고 목표는 종료 상태로 남는다. 이미 간 알림은 회수하지 않고 **다시 보내지 않는다**.

### FR-R10 신고

- 결과 한마디·사진은 사용자 생성물이라 기존 신고 경로(`report` 함수)의 대상에 넣는다. 사진은 목표 커버와 같은 반려 사유 코드(성인·폭력·개인정보·저작권·기타)를 쓴다.

## 15.7 알림톡 새 템플릿 초안 (심사 제출 전 회장 승인 필요)

**확인한 공식 기준**(카카오비즈니스 알림톡 심사 가이드, ref-05 캡처에서 관찰됨): 수신자의 명시적 요청·신청에 따른 정보는 정보성으로 인정되며, 그러려면 ①본문에 발송 근거가 된 신청 사실을 적고 ②1회 신청에 1회 발송이 원칙이고 신청 범위 밖 정보를 넣지 않는다. 다른 재화·서비스 홍보가 섞이거나 추가 요청 없이 반복 발송하면 광고성이다. 변수만으로 된 본문, 버튼명에 변수가 있으면 반려. 개인정보가 들어가거나 유추되는 이미지는 발송 불가. 신고가 다수면 사업자등록번호 기준으로 알림톡·브랜드 메시지가 영구 중지될 수 있다.

**초안 v1 (`CHEER_RESULT_POSTED_V1`, 기본형 텍스트)**

```
[해낼게] 응원하신 목표의 결과 소식

#{주인공}님이 회원님이 응원하신 목표 "#{목표}"의 결과를 올렸어요.

이 메시지는 회원님이 응원하실 때 신청하신 결과 알림으로, 응원하신 목표 1개당 1회만 발송됩니다.

[버튼: 웹링크] 결과 보기 → https://haenael-ge.vercel.app/g/#{목표주소}
```

| 항목 | 값·이유 |
|---|---|
| 변수 | `#{주인공}`(표시 이름, 30자) · `#{목표}`(30자로 자름, 현행 CHEER_RECEIVED 와 같은 규칙) · `#{목표주소}`(목표 slug). 예시값 필수: 윤도경 / 이번 학기 평점 4.0 / abc123 |
| 결과 판정을 안 넣는 이유 | 성공 축하 문구("해냈어요!")를 넣으면 실패 결과에 같은 템플릿을 못 쓰고, 감탄·축하 표현은 홍보성으로 읽힐 여지가 있다. 중립 문구 1종으로 두 결과를 덮는다(Kickstarter 결과 중립 알림, ref-01) |
| 넣지 않은 것 | "공유하기"·"다시 응원하기"·"다음 목표"·클로버·결제·이벤트·이모지. 전부 신청 범위 밖이거나 서비스 홍보로 읽힌다 |
| 버튼 | 웹링크 1개, 이름 고정 "결과 보기". 링크 도메인은 운영 주소 정본(D-046) |
| 발신 프로필 | 기존 해낼게 채널(`KAKAO_ALIMTALK_PFID`) |
| 검수 의견란에 적을 것 | 발송 조건: 응원 결제 완료 화면에서 결과 알림을 직접 신청한 회원에게, 그 목표의 주인이 결과를 올렸을 때, 목표 1개당 1회. 반복 발송 없음 |

**광고성 판정 위험 (높은 순)**

| # | 위험 | 등급 | 줄이는 법 |
|---|---|---|---|
| A1 | 링크 뒤 결과 화면에 결제 버튼이 먼저 보이면 "정보성 메시지 링크로 광고가 우선 노출" 위반 | 높음 | 알림톡 경유 진입 시 결과 화면 첫 화면(스크롤 전)에 결제·응원 버튼을 두지 않는다. 1순위 버튼은 "카톡으로 알리기" (근거: 카카오비즈니스 알림톡 운영 유의사항 "정보성 메시지에 포함된 링크를 통해 광고가 우선 노출되지 않도록") |
| A2 | 신청 기록 없는 응원자(기능 출시 전 응원자)에게 보내면 "신청하신" 문장이 거짓이 되고 신고 시 방어 불가 | 높음 | 신청자만 알림톡. 기존 응원자는 인앱(§15.14 결정 1) |
| A3 | 응원자는 결제했지 결과를 신청한 게 아니라는 판단으로 반려 | 중간 | FR-R2 의 별도 신청 버튼과 검수 의견란 설명. 반려되면 문구만 고쳐 재검수(되돌릴 수 있음) |
| A4 | 다수 신고 → 사업자번호 기준 영구 중지 → 기존 3종까지 상실 | 낮은 확률·매우 큰 피해 | 신청자 한정, 1회, 중립 문구. 출시 후 4주 신고·차단 지표를 kill-criteria 에 둔다 |
| A5 | 2026-11 심사 가이드 개정 여부 | 확인 못 함 | 2차 자료(비즈고 블로그)가 11-01 개정을 언급하나 카카오 원문 개정일은 확인 못 했다. 위 두 요건은 원문에서 관찰됐으므로 그것을 기준으로 쓴다 |

## 15.8 기존 기능·결정과의 정합 (이웃 영향)

| 이웃 | 영향 | 처리 |
|---|---|---|
| 목표 종료(`close_my_goal`) | 결과 올리기가 종료를 포함한다 | 결과 없이 끝내기로 보존 |
| 업적(D-022, `completed_goal_count`) | "해냈어요"는 자기신고 | 업적에 넣지 않는다. 완료 목표 집계는 종료 상태 그대로 |
| 결제 성공 화면(D-051 승인 시안) | 결과 알림 신청 버튼 추가 | design 델타 시안 대상 |
| 마이페이지 "내가 응원한 목표"(v0.4.0 §5.3) | 행에 "결과 나옴" 상태와 알림 신청 종 | design 델타 |
| 감사 1회 채널(v0.4.0 §5.4) | 결과 한마디가 응원자 전원에게 하는 감사 역할을 일부 대신한다 | 구현 여부 확인 못 함. 둘 다 있으면 결과 한마디가 먼저, 개별 감사는 그대로 선택 |
| 워드맵 | 결과 화면에서 응원자 본인 단어 강조 | 응원자 본인 보기에서만 |
| 응원 도착 알림톡(CHEER_RECEIVED) | 같은 발송 경로·인앱 폴백 공유 | FR-R7 도착 확인을 같이 적용 권장 |
| 분석 동의(D-054) | 결과 화면 이벤트는 동의 전 GA4 거부 기본값 | 서버 측 집계(DB)를 북극성 진실원으로 |
| 개인정보 처리방침 | 응원자 전화번호를 결과 알림에 쓴다 = 이용 목적 추가 | 출고 전 법률 검토 목록(§15.11 R-9) |

## 15.10 수락 기준(AC)과 QA 항목

> 형식: Given/When/Then(standard-planning §5). 모든 FR 에 AC 1개 이상, 엣지·실패 포함. 각 AC 는 qa-tracker 의 TC 1개 이상으로 내려간다(TC-ID 는 eng-design `test-cases` 에서 부여).
> **실기기 표기**: [실기기] 가 붙은 AC 는 에뮬레이터·데스크톱 브라우저로 대신하지 않는다. iOS 실기기 1대(카카오톡 최신) + Android 실기기 1대(카카오톡 최신)에서 각각 관찰하고, 화면 녹화 또는 캡처와 솔라피 messageId 를 증거로 남긴다. 11-25 iOS 구형 Safari 사례가 있었으므로 iOS 는 지원 최저 버전 기기를 1대 더 쓸 수 있으면 쓴다(없으면 미검증으로 적는다).

### FR-R1 결과 올리기

```gherkin
AC-R1-1  Given 주인이 진행 중인 자기 목표 화면에 있다
         When  "해냈어요", 한마디 "붙었다. 다들 고마워"(12자), 사진 1장을 넣고 올리기를 누른다
         Then  목표가 종료 상태가 되고 결과 화면으로 바뀐다
         And   주인 화면에 "응원자 N명에게 소식이 가고 있어요"가 보인다(N = §15.5 FR-R3 대상 수)
AC-R1-2  Given 결과 올리기 시트
         When  한마디가 0자, 공백만, 141자 중 하나다
         Then  올리기 버튼이 비활성이고 글자 수 안내가 보인다. 서버에도 같은 검증(직접 호출 시 거부)
AC-R1-3  Given 사진이 10MB 초과 또는 허용 형식 밖
         When  첨부한다
         Then  첨부가 거부되고 이유가 한 줄로 보인다. 결과 본문 입력은 유지된다
AC-R1-4  Given 남의 목표 또는 이미 종료된 목표
         When  결과 게시를 직접 호출한다
         Then  거부되고 목표 상태는 안 바뀐다
AC-R1-5  Given 주인이 "결과 없이 끝내기"를 고른다
         When  확인창에서 종료를 누른다
         Then  지금과 같이 종료되고 응원자 알림은 0건이다(회귀)
```

### FR-R2 결과 알림 신청

```gherkin
AC-R2-1  [실기기] Given 로그인 회원이 카톡 안 브라우저에서 응원 결제를 마쳤다
         When  결제 완료 화면에서 "결과 나오면 카톡으로 받기"를 누른다
         Then  버튼이 "결과 나오면 알려 드릴게요"로 바뀌고, 새로고침 뒤에도 유지된다
AC-R2-2  Given 신청한 응원자
         When  마이페이지 응원 목록에서 해당 행의 알림을 끈다
         Then  이후 그 목표 결과는 인앱으로만 온다
AC-R2-3  Given 결제 완료 화면에서 신청을 누르지 않았다
         When  결과가 게시된다
         Then  그 응원자에게는 알림톡이 가지 않고 인앱 알림 1건만 생긴다
```

### FR-R3 발송

```gherkin
AC-R3-1  [실기기] Given 응원자 2명(iOS 1, Android 1)이 결과 알림을 신청했고 카카오 전화번호가 있다
         When  주인이 결과를 올린다
         Then  두 기기 카카오톡에 "[해낼게] 응원하신 목표의 결과 소식"이 1통씩 온다
         And   솔라피 메시지 조회에서 두 messageId 의 statusCode 가 4000 이다
AC-R3-2  Given 같은 응원자가 그 목표에 3번 응원했다
         When  결과가 게시된다
         Then  그 사람에게 간 알림은 1건이다(알림 기록 수와 솔라피 messageId 수 모두 1)
AC-R3-3  Given 결과를 게시한 뒤 한마디를 고치고, 결과를 내렸다가 다시 볼 수 있게 한다
         When  각 동작을 한다
         Then  추가 알림톡·인앱 알림이 0건이다
AC-R3-4  Given 응원자 중 탈퇴 1명, 주인과 차단 관계 1명, D-057 이전 비회원 응원 1건
         When  결과가 게시된다
         Then  셋 다 발송 대상에 없고, 결과 화면 응원 수에는 셋이 모두 포함된다
AC-R3-5  Given 스테이징 환경
         When  허용 번호 목록 밖 응원자가 있는 목표에 결과를 올린다
         Then  그 사람에게는 알림톡 요청 자체가 나가지 않고 인앱만 생긴다
AC-R3-6  Given 템플릿 ID 설정값이 비어 있다
         When  결과가 게시된다
         Then  전원 인앱, 주인 화면 "앱 알림으로 보냈어요", 오류 화면 없음
AC-R3-7  Given 응원 0명 목표
         When  결과를 올린다
         Then  "응원자에게 알리기" 토글이 안 보이고 알림 0건, 결과 화면·공유는 동작한다
```

### FR-R4 결과 화면

```gherkin
AC-R4-1  [실기기] Given 응원자가 카톡에서 알림톡 "결과 보기"를 누른다(이미 로그인 상태)
         When  카톡 안 브라우저가 열린다
         Then  3초 안에 결과·한마디·사진이 보이고, "내 응원" 블록에 내 응원 날짜와 내 단어가 강조돼 있다
         And   첫 화면(스크롤 전)에 응원·결제 버튼이 없다(§15.7 A1)
AC-R4-2  [실기기] Given 같은 응원자가 카톡 안 브라우저에서 로그인이 안 돼 있다
         When  "내 응원 보려면 카카오로 로그인"을 눌러 로그인을 마친다
         Then  같은 결과 화면으로 돌아오고 "내 응원" 블록이 보인다. 로그인 버튼이 눌리지 않거나 다른 화면으로 가면 FAIL
AC-R4-3  Given 어떤 보기(주인·응원자·친구·처음 온 사람)든
         When  결과 화면 HTML 과 화면 데이터 응답을 받는다
         Then  응원별 금액 필드가 응답에 없다(CSS 로 가린 것도 FAIL, D-039 노출 계약)
         And   처음 온 사람·친구 응답에는 응원자 이름 필드가 없다
AC-R4-4  Given 익명 응원자 본인
         When  결과 화면을 연다
         Then  "익명으로 보낸 내 응원"이 보이고, 다른 계정으로 열면 그 사람 이름이 어디에도 없다
AC-R4-5  Given "이번엔 못 해냈어요" 결과, 공개 확장 안 함, PUBLIC 목표
         When  비로그인으로 링크를 연다
         Then  결과 내용 대신 "응원한 사람에게만 공개된 결과예요"와 "나도 해낼게"가 보인다
AC-R4-6  Given 사진이 검수 대기
         When  주인이 아닌 사람이 결과 화면을 연다
         Then  사진 자리에 "사진 확인 중"이 보이고 원본 사진 주소가 응답에 없다
```

### FR-R5 재공유

```gherkin
AC-R5-1  [실기기] Given 응원자가 결과 화면(카톡 안 브라우저)
         When  "카톡으로 알리기"를 누르고 채팅방 하나를 골라 보낸다
         Then  그 채팅방에 결과 카드(이미지·문장·"결과 보기" 버튼)가 뜬다
         And   다른 기기(받은 사람)에서 그 카드를 누르면 결과 화면이 열린다(iOS→Android, Android→iOS 둘 다)
AC-R5-2  [실기기] Given 결과 화면
         When  "스토리 이미지 저장"을 누른다
         Then  9:16 이미지가 기기 사진첩에 저장되고, 이미지에 금액·응원자 이름이 없다
AC-R5-3  Given 링크 복사
         When  복사한 링크를 새 브라우저에서 연다
         Then  결과 화면이 열리고 유입 출처가 결과 공유로 기록된다
```

### FR-R6 귀착과 다음 행동

```gherkin
AC-R6-1  Given 처음 온 사람이 공유 링크로 들어왔다
         When  "나도 해낼게" → 카카오 로그인 → 목표 만들기를 마친다
         Then  그 목표 생성이 원 결과에 귀착돼 북극성 집계에 1로 잡힌다
AC-R6-2  Given 응원자가 "다음 목표 소식 받기"를 눌렀다
         When  주인이 새 목표를 선언한다
         Then  응원자에게 인앱 알림 1건이 생기고 알림톡은 0건이다
```

### FR-R7 도착 확인

```gherkin
AC-R7-1  Given 알림톡 발송 API 가 200 을 돌려줬다
         When  10분 안에 솔라피 상태가 4000 이 된다
         Then  그 알림은 "도착"으로 기록되고 주인 화면 도착 수가 1 오른다
AC-R7-2  Given 수신자가 카카오톡 미사용 번호라 상태가 4000 이 아닌 실패 코드다
         When  10분 확인 시점이 된다
         Then  "도착 실패 + 상태 코드"가 기록되고 같은 사람에게 인앱 알림 1건이 생긴다(중복 2건 아님)
AC-R7-3  Given 발송 API 자체가 실패(HTTP 오류·설정 누락)
         When  발송한다
         Then  즉시 인앱 대체, 도착 확인 조회는 하지 않는다
```

### FR-R8 넛지 · FR-R9 수정·삭제 · FR-R10 신고

**steelman (이 기능을 하지 말아야 한다는 가장 강한 주장)**: 해낼게의 지금 병목은 결과 공유가 아니라 응원 결제 자체다. 운영 데이터상 잔액 보유 계정이 한 자릿수이고(persona.md 증거 등급 보정), 결과를 올릴 만큼 기한이 지난 목표와 응원자가 3명 이상인 목표는 더 적다. 이 상태에서 새 템플릿 심사·카톡 안 브라우저 실기기 QA·사진 검수까지 붙는 기능은 결제 오류·로그인 오류를 고치는 데 써야 할 일주일을 가져간다. 더구나 알림톡 신고 한 번의 꼬리 위험이 응원 도착 알림까지 끊는다. **답**: 맞는 지적이라 범위를 셋으로 줄였다. 알림톡 템플릿 1종(중립 문구로 성패 공용), 새 공개 피드 없음, 넛지는 인앱만. 그리고 출고를 2.4.x 결제·로그인 수정 QA 종결 뒤로 둔다(release_train 2.5 는 2.4.x 다음).

**premortem (8주 뒤 실패했다면 가장 그럴듯한 이야기)**: 출시 8주 뒤 기한이 지난 목표 23개 중 결과가 올라온 것은 3개뿐이었다. 주인들은 "못 해냈다"를 응원자에게 알리기 싫어서 결과 올리기를 미뤘고, 해낸 3명도 카톡 안 브라우저에서 사진 업로드가 멈춰 한마디만 올렸다. 알림톡은 결제 완료 화면 신청 버튼을 누른 응원자가 30%라 대부분 인앱으로 갔고, 인앱 알림은 앱을 다시 안 여는 응원자에게 보이지 않았다. **대비**: ①K1 게시율 지표를 4주차에 먼저 보고 넛지 문구·실패 카드를 바꾼다 ②카톡 안 브라우저 사진 업로드를 CR 실기기 행에 넣는다(AC-R1-1 을 실기기로도 돌린다) ③신청률이 낮으면 신청 버튼 위치를 응원 시트 안으로 옮기는 안을 design 에서 같이 낸다.

## 15.13 kill-criteria (기간·모집단·수치 고정)

측정 시작 = 운영에서 결과 알림 스위치를 켠 날. 모집단이 작으므로 "8주 또는 결과 게시 20건 중 먼저"를 판정 시점으로 한다.

| # | 지표 | 판정 | 행동 |
|---|---|---|---|
| K1 | 결과 게시율 = 기한 지난 목표 중 기한+14일 안에 결과를 올린 비율 | 4주차 15% 미만 | 넛지 문구·실패 카드 교체, 진입점 재설계. 8주차에도 15% 미만이면 결과 올리기를 목표 화면 보조 행동으로 내리고 확장 중단 |
| K2 | 결과 열람률 = 결과 알림 받은 응원자 중 결과 화면을 연 비율 | 8주 25% 미만 | 알림톡 문구·버튼 재심사 검토, 인앱 비중이 높으면 신청 버튼 위치 변경 |

## 15.14 회장 결정 필요 (3개)

**결정 1 · 기능 출시 전에 응원한 사람에게도 카톡 알림톡을 보낼까**
- 배경: 카카오 심사 기준은 "본문에 신청 사실, 1회 신청 1회 발송"이다. 출시 전 응원자는 결과 알림을 신청한 적이 없다.
- 옵션 A(추천): 출시 후 결제 완료 화면에서 신청한 사람만 알림톡, 기존 응원자는 인앱 알림. → 템플릿 문구 "신청하신"이 사실이라 신고·반려에 방어된다 / 안 고르면: 기존 응원자 대부분이 카톡으로는 결과를 못 받는다(앱을 열어야 본다).
- 옵션 B: 기존 응원자에게도 알림톡. → 첫 결과부터 도달이 크다 / 트레이드오프: "신청하신"이 거짓인 발송이 되고, 신고가 쌓이면 사업자번호 기준 영구 중지로 응원 도착·환전 알림까지 잃는다(ref-05 캡처 원문).
- 추천 근거: 꼬리 위험이 기존 알림 3종 전체라서 비대칭이 크다. A 로 시작해 신청률을 본 뒤 기존 응원자에게 "결과 알림 받기" 인앱 안내를 한 번 띄워 신청을 받는다.

**결정 2 · "이번엔 못 해냈어요" 결과의 기본 공개 범위**
- 옵션 A(추천): 실패 결과는 기본 응원자만, 주인이 넓힐 수 있다. → 실패도 부담 없이 올려 응원자가 소식을 받는다 / 안 고르면: 실패 결과가 공개돼 게시 회피(R-3).
- 옵션 B: 성패 상관없이 목표 공개범위를 따른다. → 규칙이 단순하고 "실패도 서사"를 퍼뜨린다 / 트레이드오프: 게시율 하락 위험.
- 추천 근거: 북극성의 분자는 해낸 결과에서 나오고, 실패 결과의 가치는 응원자에게 마침표를 주는 데 있다. 공개 확장은 언제든 되돌릴 수 있다.

**결정 3 · 알림톡 새 템플릿 `CHEER_RESULT_POSTED_V1` 카카오 심사 제출 (외부 제출 관문)**
- 무엇을: §15.7 초안 v1 문구로 솔라피 콘솔에서 검수 요청.
- 하면: 영업일 1~3일 뒤 승인되면 QA 의 실기기 행(CR-01·08·14)이 풀린다. 반려돼도 문구를 고쳐 다시 낼 수 있다(되돌릴 수 있음).
- 안 하면: 기능은 인앱으로만 돌고 "응원자에게 카톡 전달"은 출고하지 않는다.
- 추천: design 단계와 병행해 지금 제출한다. 심사가 가장 긴 선행 조건이고 문구는 화면 디자인과 독립이다. 제출 직전 `irreversible-approve.sh` 로 이 원문을 기록한다.

## 15.15 셀프심문 (CoVe) · 레드팀

**CoVe**
- Q. "결제는 이미 응원 신청이니 별도 결과 알림 신청은 마찰만 늘린다"가 맞지 않나? → 카카오 가이드 원문은 신청 사실을 본문에 적으라고 하고, 이 계정은 바로 그 이유로 08-12 에 반려됐다. 결제를 근거로 쓰면 "회원님이 응원하셔서"까지는 쓸 수 있지만 "1회 신청에 1회 발송"의 신청 대상(결과 소식)과 맞지 않는다. 견딘다. 단 신청률이 K2 를 망치면 응원 시트 안 체크로 옮기는 안을 둔다.
