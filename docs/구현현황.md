## 2026-08-22 build 작업트리 현황: 이용료 10%와 환전 잠금 A안

- 환전 공제 계산은 웹 `cashout-fee.ts`, Edge Function `withholding.ts`, DB `create_cashout_request`에서 이용료 10%, 이용료 부가세 10%, 이용료 차감 후 금액 기준 원천징수 3.3% 순서로 맞춰져 있다. 30,000원 환전의 실수령 기준값은 25,819원이다.
- 현행 신청 경로는 `/cashout` → `CashoutRequestForm` → Server Action `createCashoutRequest` → DB RPC `create_cashout_request`다. 호출처가 없던 `request_manual_cashout`은 최신 로컬 마이그레이션에서 삭제 대상으로 명시됐다.
- A안은 신청 시 총 클로버를 유지하고 신청분만 잠근다. 지급 완료 시 잠긴 수량을 총량에서 차감하며, 반려 시에는 복원이 아니라 잠금만 해제한다.
- `/me`와 `/cashout/status`는 `SplitBalanceCard`를 공용으로 사용한다. 지급 완료 전후 수량은 라이브 잔액 역산이 아니라 지급 시점 원장 스냅샷을 표시하도록 구현돼 있다.
- 상태: 작업트리에는 2차 코드리뷰의 화면·문구 지적 4건을 고친 코드와 테스트가 존재한다. 다만 `pipeline-state.core.md`의 build 판정은 아직 `changes-requested`이므로 승인 또는 완료로 해석하지 않는다.
- 배포: 신규 마이그레이션과 화면 변경은 운영 미적용이다. 운영 실지급과 화면 픽셀 대조도 미검증이다.

## 2026-08-11 build 변경 — 환전 알림톡 배선

- `notify` Edge Function이 `CHEER_RECEIVED`, `CASHOUT_REQUESTED`,
  `CASHOUT_PAID` 3종을 검증하고 타입별 메시지 빌더를 선택한다.
- 환전 신청 RPC 성공 뒤 신청자 전화번호로 `CASHOUT_REQUESTED`를 호출한다.
  멱등 재호출(`is_replay=true`)은 중복 알림을 보내지 않는다.
- 지급 완료 RPC 성공 뒤 신청자 전화번호와 은행명만 조회해 `CASHOUT_PAID`를
  호출한다. 계좌번호·금액은 payload와 로그에 포함하지 않는다.
- 두 Server Action 모두 알림 조회·호출을 별도 `try/catch`로 격리해 알림 실패가
  이미 확정된 환전 신청·지급 완료 성공 응답을 바꾸지 않는다.
- DB `notification_type_enum`에 환전 2종을 추가하는 신규 migration과 생성 타입을
  동기화했다. 기존 migration은 수정하지 않았다.
- 배포는 실행하지 않았다. 운영 enum 적용·Edge Function 반영·실 카카오 수신은
  미검증이다.
