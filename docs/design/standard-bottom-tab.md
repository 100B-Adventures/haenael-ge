# 해낼게 하단탭 노출 기준

## 한 줄 원칙

사용자가 여러 영역을 오가며 탐색하는 화면에서는 하단탭을 유지한다. 입력, 결제, 환전, 완료 확인처럼 한 과업을 끝내야 하는 화면에서는 하단탭을 숨기고, 화면 안에 다음 행동을 한 개 이상 둔다.

서비스별 세부 탭 상태는 로그인, 앱 버전, 실험군에 따라 바뀐다. 따라서 특정 앱의 픽셀을 복제하지 않고, 공식 가이드에서 공통으로 확인되는 “최상위 탐색 대 자기완결 과업”을 판정 규칙으로 쓴다.

## 판정 규칙

1. 화면의 1급 목적이 다른 콘텐츠나 사람을 계속 둘러보는 것이라면 `유지`다.
2. 화면의 1급 목적이 입력 제출, 거래 확정, 로그인, 결제 결과 확인이라면 `숨김`이다.
3. 탭을 누르는 순간 사용 중인 입력이나 거래 상태가 손실될 수 있으면 `숨김`이다.
4. `숨김` 화면은 뒤로 가기, 완료 후 이동, 상태 확인 중 하나를 반드시 제공한다.
5. 상세 화면도 다음 대상을 연속 탐색하는 구조면 `유지`할 수 있다. 전체화면 워드맵처럼 몰입해 읽는 보조면은 `숨김`이다.
6. 화면 제목만 보고 판정하지 않는다. 같은 “관리”라도 여러 목표를 둘러보는 `/my`는 `유지`, 목표 하나를 수정하는 `/me/goal/[id]`는 `숨김`이다.

## 전체 화면 판정

| 화면 | 경로 | 판정 | 근거·다음 행동 |
|---|---|---|---|
| 랜딩 | `/` | 유지 | 서비스 탐색과 최상위 진입. 잠긴 탭은 온보딩으로 연결한다. |
| 이용안내 | `/how` | 숨김 | 한 문서를 읽는 보조면. 시작하기 또는 홈으로 돌아간다. |
| 온보딩 | `/onboarding` | 숨김 | 목표 입력·로그인 단일 과업. 저장 또는 취소가 다음 행동이다. |
| 공개 목표 | `/g/[slug]` | 유지 | 여러 목표·친구를 탐색하는 공개면. 응원하기가 본문 CTA다. |
| 결제 성공 | `/payment/success` | 숨김 | 거래 결과 확인. 목표로 돌아가기가 다음 행동이다. |
| 결제 실패 | `/payment/fail` | 숨김 | 거래 오류 복구. 다시 시도 또는 홈이 다음 행동이다. |
| 내 홈 | `/me` | 유지 | 여러 목표와 활동의 최상위 탐색면. |
| 내 워드맵 전체보기 | `/wordmap/[goalId]` | 숨김 | 한 워드맵에 몰입하는 보조면. 관리로 돌아가기가 다음 행동이다. |
| 환전 신청·확인·완료 | `/cashout` | 숨김 | 돈이 움직이는 단일 거래. 해낼게 관리, 상태 보기가 다음 행동이다. |
| 환전 상태 | `/cashout/status` | 숨김 | 거래 상태 확인. 관리 또는 새 신청이 다음 행동이다. |
| 환전 내역 | `/cashout/history` | 숨김 | 금융 기록 확인. 관리 또는 환전 신청이 다음 행동이다. |
| 친구 목록 | `/friends` | 유지 | 여러 친구를 반복 탐색한다. |
| 친구 목표 상세 | `/friends/[friendId]` | 유지 | 다른 목표·친구로 이어지는 탐색면이다. |
| 친구 초대 | `/invite` | 유지 | 최상위 탭 자체이며, 초대 대상을 바꾸며 반복 사용할 수 있다. |
| 초대 수락 | `/invite/[token]` | 숨김 | 특정 초대의 수락 단일 과업. 수락 후 친구 목록이 다음 행동이다. |
| 업적 | `/me/achievements` | 유지 | 관리 영역 안의 반복 조회 화면이며 상태 손실이 없다. |
| 목표 관리 | `/me/goal/[id]` | 숨김 | 목표 하나의 편집·종료 과업. 저장 또는 관리로 돌아가기가 다음 행동이다. |
| 해낼게 관리 | `/my` | 유지 | 여러 목표·활동·설정을 탐색하는 최상위 면이다. |
| 약관·개인정보·아동 안전 | `/terms`, `/privacy`, `/child-safety` | 숨김 | 문서 읽기 보조면. 브라우저 뒤로 가기를 사용한다. |
| 관리자 | `/admin` | 숨김 | 일반 사용자 IA 밖의 운영 도구다. 별도 관리자 내비게이션을 쓴다. |

## 구현 계약

- `ReceiverBottomNav.shouldShowBottomNav()`이 동적 화면의 최종 판정을 소유한다.
- 환전 경로 전체와 결제 결과, 온보딩에서는 하단탭을 렌더하지 않는다.
- 환전 신청 화면의 다음 행동은 `해낼게 관리로 돌아가기`, 완료 화면의 다음 행동은 `진행 상태 보기`다.
- 하단탭을 숨긴 화면은 셸의 64px 하단 여백도 함께 제거한다.

## 반례 점검

- 이 기준이 틀릴 가능성이 가장 큰 지점은 “상세는 항상 숨김”으로 과잉 일반화하는 것이다. 친구 상세는 다음 목표와 초대로 탐색이 계속되므로 유지한다.
- 돈 흐름에서 탭을 유지하면 빠른 이동이라는 장점이 있지만, 작성 중 계좌·금액 상태를 버릴 위험이 더 크다. 환전은 회장 확정과 업계의 자기완결 거래 패턴이 일치하므로 숨김이 맞다.
