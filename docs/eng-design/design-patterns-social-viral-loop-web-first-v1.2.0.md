## 1. 이 라인의 지배 패턴 — 규칙은 데이터, 집행은 코드

**문제의 형태**: 법적 고지 노출 규칙은 2026-10-17 에 표로 정해졌는데 v1~v4 네 판 연속 한 화면씩 어긋났다. 표를 아는 코드가 없었고 화면을 고칠 때마다 사람이 기억으로 다시 판단했기 때문이다. **같은 결정이 네 번 새로 내려졌을 뿐 한 번도 집행되지 않았다**(D-032).

**패턴**

```text
① 규칙을 데이터로 둔다        → 단일 상수 또는 JSON 한 파일 (SSOT)
② 렌더·경계가 그 데이터를 읽는다 → 표에 없으면 "그리지 않는다"가 아니라 "노드를 만들지 않는다"
③ 검사가 같은 데이터를 읽는다   → 경계와 테스트가 각자 배열을 들면 갈라진다
④ 데이터 밖 사용을 린트가 반려한다 → 우회 경로를 기계가 막는다
```

이 라인에서 이 패턴을 쓰는 자리는 여섯이다.

| 규칙 | ① 데이터 | ② 집행 | ④ 검사 |
|---|---|---|---|
| 법적 고지 노출 | `web/src/lib/legal/exposure.ts` | `LegalFooter.tsx` | LG-01~05 |
| 보호 라우트 | `qa/contracts/protected-routes.json` | `proxy.ts` | AU-01~04 |
| 수직 간격 | `globals.css :root` `--sp-0`~`--sp-6` | 카드 컴포넌트 | SP-01~02 |
| 응원 메시지 줄 수 | `--cheer-clamp-lines` | `ClampText.tsx` | CL-01~04 |
| 고정 CTA 자리 | `--cta-h` | 렌더 시점 대조 | SP-03 |
| 비회원 금지 필드 | api-contract §A.2 목록 | **서버 응답 스키마** | GT-01~02 |

**반례로 쓰지 말 것**: 화면 id 를 코드에 하드코딩해 분기하는 것, 표를 주석으로만 적는 것, 같은 목록을 두 곳에 복사하는 것.

## 2. 인가 패턴

### 2.1 3층 패턴 (경계 · 페이지 · 데이터)

```text
proxy.ts        낙관적 선제 차단   → 셸 HTML 을 아예 보내지 않는다. 최종 판정은 아니다
page.tsx        인증 재확인        → Server Action 은 경계가 덮지 못하므로 여기가 필요하다
RPC · RLS       최종 인가          → auth.uid() 가 당사자인지 함수 내부에서 재검사
```

근거: Next.js 공식 인증 가이드. 경계는 선제 리다이렉트용이고 보안 검사는 데이터에 가까운 곳에서 다시 한다.

**안 쓰는 것**: 경계만 믿는 구조(Server Action 구멍), 레이아웃에서 `redirect()` 로 막는 구조(스트리밍 타이밍에 다시 의존).

### 2.2 스트리밍 전에 판정한다

`redirect()` 가 스트리밍 시작 후에 던져지면 Next 는 **상태 200 + 클라이언트 meta 태그**로 처리한다(공식 문서). 그러면 회원 셸이 먼저 전달된다(운영 `/me` 실측: 200, 25,241바이트, 2.5초 뒤 이동).

**규칙**: 인증 판정은 **첫 await 보다 앞**, 가능하면 요청 경계에 둔다. 판정 뒤에 비동기 작업을 넣는 것은 괜찮고, 판정 앞에 넣는 것이 결함이다.

### 2.3 공개 경계는 주소가 아니라 객체 정책으로 가른다

FRIENDS 목표의 커스텀 커버는 비공개 버킷에 두고 친구 확인 후 120초 Presigned URL(서명이 붙은 임시 접근 주소)로만 내려준다(D-019). **행 수준 보안은 공개 Storage 주소 직접 접근에 적용되지 않는다.** 주소 이름을 어렵게 만드는 것은 경계가 아니다.

## 3. 응답 투영 패턴 (최소 노출)

**원칙: 가린다는 것은 보내지 않는다는 뜻이다.**

| 하는 것 | 안 하는 것 |
|---|---|
| 서버가 필드를 **응답 스키마에서 제외** | CSS `filter: blur()` 로 가리기 |
| 클라이언트에 집계값만 전달 | 전체 배열을 보내고 화면에서 자르기 |
| 익명이면 `profile_image`·`supporter_name` 을 `null` 로 | 익명 플래그만 보내고 값은 그대로 두기 |
| `anon` 에게는 토큰 소지 근거가 있는 최소 미리보기만 | 비회원에게 타인 식별자 전달 |

근거: OWASP WSTG Excessive Data Exposure. 검사도 픽셀이 아니라 **네트워크 raw 응답과 DOM 텍스트**를 본다(GT-01).

**금액 비공개는 투영으로 집행한다**(D-003). 금액을 보내고 화면에서 숨기지 않는다. `clover_amount`·`amount_krw`·`rank` 는 소셜 응답의 **key 자체가 없다.**

## 4. 디자인 토큰 패턴

### 4.1 두 계열을 섞지 않는다

| 계열 | 용도 | 예 |
|---|---|---|
| `--space-*` (기존) | **페이지 레벨** 여백 | `--space-mobile-gutter`·`--space-page-y`·`--space-bottom-safe` |
| `--sp-0`~`--sp-6` (R10 신설) | **컴포넌트 안 수직 관계** | 라벨-값 `--sp-1` · 묶음 안 `--sp-2` · 카드 안쪽 상하 `--sp-3` · 묶음 간 `--sp-4` · 섹션 `--sp-5` · 큰 단락 `--sp-6` |

**선언 위치는 `web/src/app/globals.css` 의 `:root` 한 곳이다.** 새 토큰 파일을 만들지 않는다. 쪼개면 정본이 둘이 된다.

### 4.2 관계로 고르고 크기로 고르지 않는다

스케일은 지어내지 않았다. 25화면의 모든 세로 여백을 세어 빈도 상위에서 골랐다(12px 165회 · 4px 165 · 8px 101 · 16px 79 · 2px 98 · 24px 9). 따라서 **"8px 보다 좀 넓게" 가 아니라 "이 둘은 묶음 안 항목이다" 로 고른다.**

### 4.3 적용 범위를 넓히지 않는다

`DESIGN.md` 가 본문 문단·목록 행의 개별 여백을 **미적용**으로 명시했다(고유값 24종 중 토큰 적중 56%). 설계도 거기까지 넓히지 않는다. 범위를 모호하게 넓히면 "토큰을 쓰는 척" 이 된다.

### 4.4 카드 안쪽 상하는 같은 토큰

위를 `--sp-3` 로 줬으면 아래도 `--sp-3` 다. 카드 안 첫 자식·마지막 자식에 `margin` 을 더 얹어 비대칭을 만들지 않는다(R9 의 원인이 캡션의 `margin-bottom:8px` 였다).

**예외**: 라벨과 값이 `--sp-1` 로 붙으면 위아래가 비대칭으로 **보이는 것이 정상**이다. 기계 검사의 그 축은 **경고이고 차단 조건이 아니다**(`DESIGN.md` F 축).

### 4.5 폐지된 토큰은 지운다

R2 로 자물쇠 배지가 폐지됐으므로 `--tabbar-lock-size` 를 제거한다. **그리는 수단을 남기지 않으면 마크업이 남아도 그려지지 않는다**(프로토타입이 쓴 것과 같은 방식).

## 5. 쓰기 경로 패턴 (상태기계 + 정리)

```text
PENDING_UPLOAD ──(소유자: Storage PUT)──> PENDING_UPLOAD
       │                                        │
       │(소유자: finalize · MIME·크기·해시 검증)  │(24시간 경과)
       ▼                                        ▼
    REVIEW ──(관리자)──> APPROVED | REJECTED   정리 작업이 객체 → 행 순으로 삭제
```

**규칙 넷**

1. **전이마다 주체를 적는다.** 주체가 아닌 역할의 시도는 거부한다.
2. **승인 전 상태가 기존 활성 자산을 바꾸지 않는다.** 활성 교체는 승인 시점의 원자 연산이다.
3. **중단 상태를 치우는 주체를 반드시 둔다.** 치우는 주체가 없는 상태는 누적된다. 이 공백이 회장이 본 업로드 오류의 재발 자리였다.
4. **객체 먼저, 행 나중.** 객체 삭제가 실패하면 행을 남기고 재시도한다. 반대로 하면 고아 객체가 생긴다.

선례: `docs/eng-design/cashout-account-purge-scheduler.md`.

### 5.1 멱등 경계를 분리한다

| 연산 | 멱등 | 왜 |
|---|---|---|
| 초대 **생성** | 비멱등 | 매번 새 토큰이어야 한다 |
| 초대 **수락** | 관계 기준 멱등 | 같은 수락자의 재시도는 같은 관계를 반환. 다른 수락자의 재사용은 거부 |
| 커버 **확정** | 자산 기준 멱등 | 같은 자산의 재확정은 같은 `REVIEW` 를 반환 |
| 커버 **심사** | 비멱등 + 409 | 이미 심사된 자산의 재심사는 거부 |
| 응원 → 친구 생성 | 쌍 기준 멱등 | 정렬된 쌍 UNIQUE 가 보장. 응원과 초대가 동시에 와도 1건 |

## 6. 조회 패턴 (N+1 금지)

| 패턴 | 적용 |
|---|---|
| **일괄 IN 조회** | 목표 집계: `.in("goal_id", goalIds)` 1회. 목표 수에 비례해 왕복이 늘지 않는다 |
| **목표별 최근 1건** | `DISTINCT ON (goal_id) … ORDER BY goal_id, created_at DESC` 전체 1회. 목표마다 `LIMIT 1` 을 돌리지 않는다 |
| **상한 있는 투영** | 아바타는 **최대 3개**만 보낸다. 전체 응원자 배열을 보내고 화면에서 자르지 않는다 |
| **일괄 서명 발급** | `createSignedUrls(paths, TTL)` 1회(`server.ts:103` 구현 확인). 커버마다 `createSignedUrl` 을 부르지 않는다 |
| **단일 read model** | `/my` 는 `my_social_dashboard()` 한 번으로 프로필·목표·업적·큐를 받는다. 화면 블록마다 RPC 를 추가하지 않는다 |

**검사로 집행한다**: 목표 1개와 20개의 서버 왕복 횟수가 같아야 한다(CS-02). 숫자가 다르면 N+1 이 들어온 것이다.

## 7. 안 쓰는 것

| 안 쓰는 것 | 왜 |
|---|---|
| **전역 상태 라이브러리** (Redux·Zustand 등) | 이 라인의 상태는 서버 데이터와 한 화면 안의 선택뿐이다. 서버 컴포넌트 + URL 파라미터로 충분하고, 전역 저장소를 두면 공개범위 판정이 클라이언트로 샌다 |
| **클라이언트 측 공개범위 판정** | 판정은 RPC 내부에서만. 클라이언트 분기는 표시용이고 경계가 아니다 |
| **CSS 로 가리는 인가** | 가린 것이 아니라 보낸 것이다(§3) |
| **낙관적 UI 로 쓰기 성공 표시** | 커버 승인·친구 맺기·초대 수락은 서버 확정 뒤에만 성공으로 표시한다. 토스트가 아니라 상태 변화를 본다 |
| **방향·업적을 컬럼으로 저장** | 응원이 추가될 때마다 갱신해야 하고 그 갱신이 빠지면 화면이 거짓을 말한다. **DB 원장에서 매번 집계한다**(D-022 의 "반증 가능한가" 기준) |
| **`<details>` 요소** | 제품 화면 금지. 접기는 꺾쇠 하나로(R8 · `COLLAPSE_POLICY`) |
| **자물쇠·차단 배지** | 다음 행동이 없는 신호다. 가치 미리보기 + 시작 행동으로 대체(R2) |
| **외부 이미지 모더레이션 공급자** | 공급자·비용·오탐 정책 미결정. 1차는 수동 검수로 완결(비범위 유지) |
| **새 색·반경 토큰** | 승인 토큰만 쓴다. 접근성 하한과 충돌하면 하한이 이기고 그때 시안 정본을 고친다(D-023) |
| **구멍 하나에 검사 하나** | 새 결함이 나오면 검사 스크립트를 새로 만들지 말고 §1 의 데이터에 줄을 추가한다(CLAUDE.md §9) |
