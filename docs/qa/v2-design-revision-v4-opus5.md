## 2. 모션 측정 (D-030-A · 화면별)

### 2-1. 측정 방법이 두 번 바뀐 경위 (다음 사람이 같은 함정에 빠지지 않게)

| 판 | 방법 | 왜 틀렸나 |
|---|---|---|
| 1차 제출 | `go(id)` 직후 + 다시 재생 직후의 400ms 창을 스크린샷으로 샘플 | **모션이 도는 구간만 골라 쟀다.** 회장이 파일을 열고 눈이 닿는 시점(1초 뒤)은 이미 끝난 뒤다 |
| 재검증 | 파일 열고 1.5초 대기 후 `page.screenshot` 픽셀 비교 | **CDP `Page.captureScreenshot` 은 compositor 스레드에서 도는 `transform`·`opacity` 애니메이션을 못 잡는다.** 실측: 워터마크가 9px 움직이고 점 opacity 가 0.999→0.74 로 변하는 동안에도 PNG 가 바이트 동일했다. "픽셀 변화 0" 이 모션 부재를 뜻하지 않았다 |
| 확정(이 표) | `Page.startScreencast` 합성 프레임 + 렌더 값 실측 두 축 | 스크린캐스트는 합성 결과라 회장 눈과 같은 경로다. 다만 **헤드리스는 입력이 없고 합성 애니메이션만 도는 화면에서 프레임 생산을 멈춘다**(해낼게 관리·환전 내역이 정지 1.3초에 프레임 1개, 같은 세션의 다시 재생 구간은 25~37개). 그래서 화면 안에 보이는 애니메이션 요소의 렌더 값(transform·opacity·배경·색·margin·위치)을 1초간 3회 샘플해 변화를 함께 센다 |

### 2-4. 화면별 지속 ambient (장식이 아니라 상태에 복무한다)

`standard-design.md` §11 "의미 없는 장식 모션 금지" 를 지키려고 화면이 말해야 할 상태에만 걸었다. 전부 제자리 모션이고 `prefers-reduced-motion` 에서 정지한다.

| 화면 | 무엇이 움직이나 | 의미 |
|---|---|---|
| 전 화면 | 워드마크의 클로버 점이 숨 쉰다 · 안 읽은 알림 배지가 맥박한다 | 브랜드 앰비언트 · 읽지 않은 것이 있다는 상태 |
| 홈 | 목표 배너의 클로버 워터마크와 잔액의 클로버가 아주 느리게 떠 있는다 | 응원이 쌓이는 중인 내 목표 |
| 초대·연결 | 카카오 말풍선 미리보기가 떠 있는다 | 지금 보내면 이렇게 간다 |
| 초대 수락 | 초대한 사람 아바타에서 클로버 링이 번진다 | 초대가 아직 열려 있다 |
| 친구 | 서로 응원 배지와 진행바 색이 오간다 | 그 관계가 지금도 오가는 중 |
| 해낼게 관리 | 목표 배너 워터마크가 떠 있는다 | 진행 중인 목표 |
| 환전 내역 | 확인 중 한 건의 행과 배지가 맥박한다(완료·반려 행은 정지) | 지금 처리되고 있다 |
| 로그인 | 카카오 버튼 테두리가 아주 옅게 숨 쉰다 | 지금 누르면 이어진다 |
| 워드맵이 있는 화면(랜딩·공개 목표·목표 관리·응원 워드맵·친구 상세·도파민) | 응원 단어가 둥둥 떠 있고 하트·클로버가 올라간다 | 기존 D-027-E 연출 유지 |

구현 메모: 홈·초대·해낼게 관리·환전 내역은 CSS 키프레임이 합성 레이어로 올라가 캡처에 아무 흔적을 안 남겼다. 그래서 그 자리들은 `requestAnimationFrame` + 타이머로 `margin-top` 을 갱신하는 앰비언트(`.amb-float`)로 바꿨다. 레이아웃 속성이라 눈과 캡처가 같은 것을 본다.

### 2-5. 화면별 모션 목록

프로토타입 화면 고정 도크의 **목록** 버튼을 누르면 그 화면의 모션이 이름으로 나열되고, 항목을 누르면 그 순간이 재생된다. 전 화면 공통 2종(화면 전이 fade, 첫 화면 블록 순차 rise)에 화면별 모션이 더해진다. 예: 랜딩 4종, 응원 워드맵 5종, 업적 6종, 결제 성공 3종.
