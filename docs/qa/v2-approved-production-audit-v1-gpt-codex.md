## 1. 결론

**QA 판정은 반려다.** 승인 시안 21개 화면과 승인 시안에 없는 초대 수락 화면 1개를 390px, 1280px에서 대조했다. 총 22개 화면 중 `일치 0`, `불일치 15`, `미확인 7`이다.

가장 큰 결함은 네 가지다.

1. 비회원 랜딩과 공개 목표에 승인 시안의 잠금 하단탭이 없다.
2. 마이페이지의 정보 구조가 승인 시안과 다르다. 승인 시안의 활동 메뉴, 받은 응원·보낸 응원, 환전 내역, 환경설정 구조 대신 내 목표, 3개 업적 카드, 소속감 큐가 한 화면에 놓였다.
3. 초대 화면이 관계 경험 대신 토큰, SHA-256 hash, `PUBLIC`, `FRIENDS`, 7일 만료를 사용자에게 노출한다.
4. 현재 친구 생성은 초대 수락에 묶여 있어 D-024와 충돌한다. 응원 확정 시 양방향 친구 생성과 과거 이력 소급이 구현되지 않았다.

## 2. 대조 범위와 제약

### 2.1 증거 수량

| 항목 | 결과 | 증거 등급 |
|---|---:|---|
| 승인 시안 화면 | 21개 | 근거 확인 |
| 추가 점검 화면, 초대 수락 | 1개 | 근거 확인 |
| 뷰포트 | 390px, 1280px | 관찰됨 |
| 캡처 | 88장 | 관찰됨 |
| 대조쌍 | 44쌍 | 테스트됨 |
| 대조쌍 검사기 | 44쌍 통과, 크기 불일치 0, 통짜 덤프 0, 좌우 순서 위반 0 | 테스트됨 |
| 운영 쓰기 요청 | 0건 | 관찰됨 |

### 2.2 운영 계정 제약

운영 읽기 전용 계정은 Auth 로그인에는 성공했지만 `member` 행이 없었다. 본인 목표와 친구 데이터도 없었다. 공개 목표는 1건 이상 조회됐다.

따라서 다음 화면은 정상 데이터 상태를 보지 못했다.

- 회원 홈은 `/me`에서 `/onboarding`으로 리다이렉트됐다.
- 목표 상세는 유효한 본인 목표가 없어 404였다.
- 친구 상세는 유효한 친구 관계가 없어 404였다.
- 초대 생성은 공개 목표가 없어 생성 버튼이 나타나지 않았다.
- 관리자 화면은 관리자 권한이 없어 404였다.

이 상태들을 통과로 세지 않았다. 확인하지 못한 화면은 `미확인`으로 남겼다.

## 6. D-024 영향 범위

D-024 정본은 `응원 확정 시 양방향 친구`, `과거 이력 소급`, `초대 링크는 미가입자 유입 통로`다. 현재는 `accept_friend_invite`만 `friend_connection`을 생성한다.

| 영역 | 현재 | D-024 반영 범위 | 종료 증거 |
|---|---|---|---|
| 응원 주문 | 로그인 응원자의 `cheer_id`와 `supporter_member_id`를 주문 생성 때 귀속 | 주문 생성이 아니라 결제 `CONFIRMED` 트랜잭션에서 관계 생성을 보장해야 함 | 결제 확정 1건 뒤 양방향 조회에서 친구 1쌍 |

| 문서·테스트 | FDD와 테스트가 초대 수락 친구 모델을 전제 | PRD, FDD, API contract, ERD, 테스트케이스, 시안의 관계 정의를 D-024로 갱신 | 추적표에서 D-024가 화면·DB·E2E까지 연결 |

### 기술설계에서 닫아야 할 결정

1. `REMOVED` 관계가 새 응원으로 자동 복구되는가. 추천은 자동 복구 금지다. 사용자가 끊은 관계를 결제가 되살리면 관계 제어권을 침해한다.
2. 익명 응원을 나중에 로그인 계정에 귀속할 것인가. 추천은 명시적 계정 승격 이후에만 귀속하는 것이다. 추정 매칭은 금지한다.
3. 기존 초대 수락만으로 생성된 관계를 유지할 것인가. 추천은 기존 관계는 보존하되 신규 초대 수락은 친구 생성 대신 목표 진입으로 바꾸는 것이다.
