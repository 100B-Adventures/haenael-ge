무료 staging의 실제 OAuth 시작·callback·보호 라우트를 대상으로 실행했습니다. 제품 인증 코드는 이미 승인 설계대로 연결돼 있어 재구현하지 않고, 누락됐던 실제 Kakao E2E를 추가했습니다.

G4-AUTH-02 실제 UI와 서버 결과

  • 취소 callback은 /?auth_error=cancelled로 복귀하고 재로그인 링크가 노출됐습니다.
  • 잘못된 state와 가짜 code는 HTTP 307, auth_error=invalid_state, 세션 쿠키 0으로 거부됐습니다.
  • 비인증 /my는 HTTP 307과 정확한 next=/my를 반환했고, 마이페이지 개인정보 DOM은 0건입니다.
  • Playwright headless 실행은 1/1 PASS, console·page error 0입니다.

G4-AUTH-01 외부 차단 증거

  • haenael 전용 Chrome에서 Kakao 쿠키 13개를 값 노출 없이 읽어 headless 컨텍스트에 주입했습니다.
  • 실제 Kakao authorize 화면은 계정 비밀번호 입력을 요구했고 테스트는 external_kakao_session_expired로 종료됐습니다.
  • 메인 Chrome의 최소 쿠키 프로필을 복제한 두 번째 headless 시도도 제한시간 안에 사용할 수 있는 세션을 만들지 못했고, 생성한 임시 프로필과 프로세스는 정리했습니다.
  • 따라서 Kakao 동의 → callback → Supabase 세션 → /my 성공 왕복은 PASS로 승격하지 않았습니다.
