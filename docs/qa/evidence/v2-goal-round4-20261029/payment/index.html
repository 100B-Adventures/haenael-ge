Toss Payments 샌드박스 종단 검증

G4-PAY는 테스트 주문 생성부터 Toss Payments 샌드박스 승인 콜백과 주문 상태 반영까지 확인하는 결제 검증 범위입니다. 실제 staging과 Toss Payments 샌드박스를 사용했고, mock 승인이나 성공 URL 강제 이동은 사용하지 않았습니다.

범위 판정: BLOCKED · BankPay 데스크톱 보안 프로그램을 통한 외부 계좌 인증 필요

필수 입력 검증과 외부 인증 전환

  • 기존 자동화는 첫 번째 다음 클릭 직후 성공으로 간주해 빨간 validation 화면에서 콜백을 기다렸습니다. 필수 label과 실제 DOM 전환을 검증하도록 수정했습니다.
  • 관찰된 popup은 Toss Payments의 /transfer/bankpay와 BankPay의 /StartBankPay.do입니다.
  • Toss Payments transfer-authentication/BANKPAY/prepare POST와 BankPay StartBankPay.do POST가 모두 HTTP 200이었습니다.
  • 그 다음 단계는 브라우저 입력이나 제품 callback이 아니라 데스크톱 뱅킹 보안 프로그램 설치와 실제 계좌 인증입니다. 이 경계를 우회하지 않았으므로 성공 콜백과 DB 상태 반영은 PASS로 기록하지 않았습니다.

취소·오류 경로

  • 금액이 다른 callback은 HTTP 400으로 거부됐습니다.
  • 취소 뒤 주문은 승인 상태로 변하지 않았습니다.
  • 실패 callback과 중복 성공 callback은 성공 승인을 선행해야 검증할 수 있어 외부 인증 경계와 함께 BLOCKED입니다.
  • staging의 PAYMENTS_ENABLED는 검증 뒤 false로 복구했고, TOSS_SECRET_KEY는 남지 않았으며 테스트 fixture 잔여도 0건입니다.

소스와 기준

  • Toss Payments 실제 E2E 원문
  • 검증 대상 staging
  • Toss Payments 결제위젯 연동 공식 문서
  • Toss Payments 결제창 SDK 공식 문서
  • Toss Payments 테스트 환경 공식 안내

필수 입력 selector와 validation 전환 결함은 수정했지만 실제 승인 콜백은 BankPay 외부 계좌 인증을 통과하지 못했습니다. 따라서 주문 승인·상태 반영과 실패·중복 콜백을 포함한 결제 검증 범위 전체는 BLOCKED이며, 운영 결제·실제 과금·운영 배포는 실행하지 않았습니다.
