4. 기능·디자인 증거 판정

편집·저장·reload·목록 전개

01~06 이미지를 전부 직접 열었다. 편집기 열기, 제목 입력, 저장 후 reload된 제목, 8명 preview, 18명 전개가 순서대로 존재한다. 독립 실행의 임시 캡처에서도 같은 흐름이 재현됐다.

04 reload 캡처는 제목은 정상 반영됐지만 cover와 첫 avatar가 loading placeholder인 시점에 찍혔다. 이는 screenshot이 domcontentloaded와 제목 assertion 직후 생성된 데모 품질 제한이다. reload 영속성은 실제 DOM assertion으로 통과했고, 이후 05·06·08에서는 응원자 이미지와 목록이 완전히 렌더됐다. 따라서 기능 결함이나 출고 차단으로 세지 않는다.

승인본과 staging 대조

07과 08은 모두 390×844이고 첫 응원자 card top이 72px다. 목록 행 구조, avatar·이름·메시지·횟수 pill·시간의 열 배치, 경계선, 하단 nav가 같은 계열로 렌더된다. 22.14% pixel delta는 prototype 11개와 staging fixture 18개의 DOM 데이터 행, 이름, 메시지, 횟수 차이를 포함한다. 픽셀 동일성은 주장하지 않으며 배치·component·pill 정합을 판정했다.

기존 evidence의 visible_rows 명칭은 viewport 안에 실제로 보이는 행이 아니라 렌더된 DOM 행 수를 뜻했다. 표시 문서는 DOM 데이터 행으로 교정했다. 비교 자체의 viewport·scroll 정렬에는 영향이 없다.
