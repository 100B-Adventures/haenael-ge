해낼게 S3 독립 코드·로그 검토 v1

STAMP: 2026-10-27 16:56 KST | model gpt-codex(API model ID 미노출) | agent qa-verifier | skills qa, review | scope S3 lightweight code/log review only | verdict BLOCKED_FOR_INDEPENDENT_EXECUTION

기반 포맷: S2 독립 QA 보고 구조. 이번 문서는 브라우저·E2E·DB 쓰기를 실행하지 않은 중간 코드리뷰이며 S3 완료·PASS를 주장하지 않는다.

결론

현재 F5 7/7과 F6 v3 16/17 로그는 기능 결함보다 테스트 복구가 진전됐음을 보여준다. 관리자 selector 수정, 동적 fixture 식별, 보안·동시성 assertion은 타당하다. 다만 UI 클릭 직전 authenticated HTTP probe와 결제 flag 수명주기 재현성 2건은 최종 독립 실행 전에 닫아야 한다. S1·S2 판정은 변경하지 않는다.

발견 사항

P1 · UI 목표 Link 클릭 직전 HTTP 200 probe가 cold UI navigation을 예열한다

  • 근거: web/e2e/social-web-first.spec.ts:2594-2597이 acceptInvitePage.request.get(expectedFriendGoalPath)로 같은 인증 cookie를 사용해 목표 상세 route를 먼저 200으로 호출하고, 그 뒤 2598-2606에서 실제 Link click·URL·DOM을 검증한다.
  • 판정: probe가 UI 클릭을 대체하지는 않는다. 실제 Link click과 friend-detail-page, 목표 제목 assertion이 남아 있어 인증 우회로 PASS시키는 구조는 아니다.
  • 차단 이유: 첫 UI navigation 전에 서버 route와 데이터 경로가 예열된다. 따라서 cold first-hit에서만 나타나는 인증·라우팅 지연을 이 실행으로는 보장할 수 없다. 이번 과제의 “HTTP 직접호출로 UI 클릭을 대체하거나 예열하지 않는다” 조건에는 맞지 않는다.
  • 최소 수정 대상: friendGoalProbe 4줄을 최종 독립 흐름에서 제거한다. HTTP 200 계약은 별도 API/route 케이스로 유지하고, 01A는 친구목록 DOM → 실제 Link click → URL → 상세 DOM만으로 끝낸다.

P1 · F6의 ORDER-ATTR 전제인 staging PAYMENTS_ENABLED=true가 spec과 canonical verify에 없다

  • 근거: ORDER-ATTR-01은 cheer-order의 201을 요구하지만 social-web-first.spec.ts의 beforeAll·afterAll에는 결제 flag 준비·복구가 없다. .goal/feature-list.json의 F6 명령도 flag 제어 wrapper를 명시하지 않는다.
  • 로그: F6 v2는 01A 실패 뒤 ORDER-ATTR가 503 payments_disabled로 실패했다. F6 v3은 worker 재시작 뒤 ORDER-ATTR가 통과했으므로, v3 외부 wrapper는 npx process 전체에서 flag를 유지한 것으로 보인다.
  • 판정: “첫 01A 실패 후 spec afterAll이 flag를 복구했다”는 가설은 현재 코드로 입증되지 않는다. 더 정확한 결론은 v2 F6가 flag off 상태에서 ORDER-ATTR를 실행했으며, 어느 runner 경계가 복구했는지는 증거 부족이다.
  • 최소 수정 대상: 제품 코드가 아니라 S3 실행 wrapper·manifest다. F6 process 시작 전 1회 enable, process 종료의 finally에서 1회 disable, 종료 후 503 payments_disabled 확인을 단일 명령으로 고정한다. Playwright worker 재시작은 flag를 건드리지 않아야 한다. 실제 Toss 호출은 계속 금지한다.
