# 완료 기준 (Definition of Done) — haenael-ge

> 회장 2026-07-28: "단위테스트로 화면만 만들면 됐다고 하지 말고, 연결/E2E/브라우저 테스트까지 기능동작 완료했을 때 '된다'고 해라."

## user-facing 기능의 "완료" = 아래 전부 관찰됐을 때만
1. **브라우저 E2E 관찰**: 실제 브라우저에서 사람이 밟는 여정(클릭→입력→제출→결과)을 직접 실행하고 화면으로 확인. 스크린샷/관찰 증거 필수.
2. **연결 검증**: UI→API/EF→DB까지 실제 데이터가 흐르는 것 확인(주문 생성·상태 전이·ledger 등).
3. **엣지 케이스**: happy 외 최소 — 잘못된 입력·중복 제출·취소·미달·권한없음 중 해당되는 것 실행.

## "완료"가 아닌 것 (보조 증거일 뿐)
- 단위테스트 PASS / 빌드 성공 / 타입체크 / curl 200 / mock PASS → **전부 보조 증거**. 이것만으로 "된다/완료" 금지. 안 본 건 "미검증".

## 보고 규칙
- QA·기능 보고에 "브라우저 E2E 관찰됨" 라인이 없으면 완료 주장 금지 → "미검증(브라우저 E2E 필요)"으로 명시.
