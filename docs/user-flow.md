## 0. 두 행위자 · 두 화면 (절대 분리 — 이전 혼선 지점)

| | 받는 사람 (주인공·공급) | 친구 (응원자·수요) |
|---|---|---|
| 목적 | 목표 선언하고 조용히 응원받기 | 친구 목표에 조용히 돈으로 응원 |
| 화면 | **① 가입 랜딩 + 목표 만들기** | **② 목표 페이지(공유 링크 타깃)** |
| 진입 | 입소문/공스타 운영계정 linktree | **인스타 바이오 링크 → ②로 직행** |
| 결과 | 클로버 적립 → 환전 | 결제(매출 발생) |

**핵심 교정(컨트롤러 draft 비판):** 친구는 **① 랜딩(홈)에 오지 않는다.** 인스타 링크는 항상 **②(특정 사람의 목표 페이지)** 로 떨어진다. 따라서 ①에는 "친구 응원하러 왔어요" CTA를 두지 않는다. 친구→자기목표 전환(role-transition)은 **②→①** 한 방향으로만 흐른다(②에서 "나도 해낼게 만들래" → ① 온보딩). 이게 자가확산 공급 고리의 진짜 입구다.

```
인스타 바이오 ─클릭─▶ ② 도경의 목표 페이지 ─결제─▶ (확산) ─"나도 만들래"─▶ ① 온보딩 ─내 링크─▶ 인스타 바이오 …
```

## 1. 받는 사람 플로우 (① 가입 → 목표 → 링크 → 수신 → 워드맵 → 환전)

### 1.1 Happy path
1. **진입** — 공스타 운영계정/프로필 linktree, 또는 ②에서 "나도 만들래" 전환. 🔒 1차 GTM=공스타 linktree.
2. **랜딩(①)** — 🔒 확정 = **C 미니멀 + 워드맵 프리뷰 하이브리드**(`landing-final.html`). 슬로건 히어로(궁금증 훅) + 컴팩트 워드맵 프리뷰(받는사람 보상 미리보기). primary CTA "시작하기" **단 하나** + 보조 "어떻게 쓰는 건가요?". (친구 CTA 없음)
3. **목표 만들기** — 🔒 입력 = 목표("○○ 해낼게")·일정(D-day)·왜(이유). 매일 인증 강제 X(진행 업데이트는 선택).
   - 🔒 가입 방식 확정 = **write-first**: 시작하기 → 목표쓰기(=C가 못 한 설명 역할) → "저장" 누를 때 AuthSheet(소셜 1탭).
4. **저장/로그인** — AuthSheet(소셜 1탭). ⚠️ write-first면 입력 draft를 로컬에 보존(로그인 실패해도 글 안 날아감).
5. **내 링크 받기** — 고유 링크 발급 → ShareLinkCard: 복사 + "인스타 바이오에 붙여넣기" 안내. 🔒 공급 활성화 핵심 한 스텝.
6. **대기/수신** — 친구 응원 도착 → 🔒 은은한 알림(감사답장 의무 없음). 누가 응원했는지 봄(🔒 익명 강제 아님), 금액은 안 봄(🔒).
7. **워드맵 → 공유(확산 고리)** — 홈은 "워드맵 보기" 단일 CTA → **워드맵 풀뷰**(꽉 찬) → **아이콘 공유**(텍스트 X): 이미지 저장 / 인스타 스토리(목표 링크 스티커 얹힘) / 링크 복사 → 친구가 스토리 보고 링크 탭 → ② 목표페이지 도착 = 🔒 확산 고리 닫힘. 워드맵은 단어·"익명의 누군가"만, 개별 후원 금액 X. (프로토 `wordmap-share.html`)
8. **환전** — 🔒 클로버가 *최소환전액 이상 모이면* 환전. KYC·3.3% 원천징수. (적립형=달성 무관 환전 🔒)
   - 🔒 **금액 표기 3층(2026-07-02 확정):** 친구/공개=비노출("N명"), 받는사람 본인 홈·워드맵=클로버 **개수(🍀 N개)만**(₩ 환산 X), **원화는 환전 플로우에서만** 현실화(진입=개수, 환전 눌러야 ₩·수수료 등장). DESIGN.md §6 정본.

### 1.2 ① 분기·상태 (dead-end 0)
| 상태 | 트리거 | 화면/다음 경로 |
|---|---|---|
| 입력 검증 실패 | 목표 빈값·일정 과거 | 인라인 에러, 저장 비활성, 채우면 복구 |
| 로그인 취소/실패 | AuthSheet 닫음·소셜 거부 | draft 유지 + "나중에 저장" → 로컬 보존, 재시도 경로 |
| 링크 복사 직후 공백 | 응원 0 | "이제 인스타에 붙여보세요" 가이드(= ②의 empty와 연결) |
| 알림 수신 | 응원 도착 | 은은한 배지. 답장 강요 없음. 무시 가능(dead-end 아님) |
| **환전 임계 미달** | 모인 클로버 < 최소환전액 | "조금만 더 모이면 환전돼요"(금액 비강조) — 막다른 길 아님, 대기 상태 |
| **환전 KYC 미완** | 환전 시도, 본인확인 전 | KYC 시트 → 완료 후 환전. 미성년이면 §5-4·❓ 연령게이트 |
| **목표 마감(D-day 경과)** | 일정 지남 | 🔒 적립형=달성 무관 환전 가능. 페이지는 "마감됨" 칩, **응원 계속 가능**(❓§5-4 회장 확인) |
| 계정/목표 삭제 | 본인 삭제 | 확인 모달 → 삭제 시 링크는 "종료된 목표" 안내(②에서 404 아님) |

### 1.3 받는사람 재방문·관리 진입 (2026-07-19 보완 — 갭1·갭2, 회장 승인)

> 실측 갭: 목표 주인이 자기 공개링크(`/g/[slug]`)를 열면 친구용 화면만 보이고 `/home`(응원 확인·환전) 진입점이 없었다.
> 프로토: `WIREFRAMES/haenael-receiver-manage-v1-fable.html` (라우팅 허브 — 화면·뷰포트·상태 토글).

**진입 동선 확정안 = (a)+(b) 조합** ((c) 전역 헤더는 MVP 보류 — 공개 화면 단일 CTA·Discreet 훼손):
- **(a) 세션 라우팅**: `/` 진입 시 세션 有+목표 有 → `/home` 리다이렉트, 세션 有+목표 無 → `/onboarding`, 세션 無 → ① 랜딩. 로그인 완료·알림(카카오 알림톡) 딥링크도 `/home` 직행.
- **(b) owner bar**: 본인 세션으로 `/g/[slug]` 열람 시 상단에 "내 목표예요 · 확인 안 한 응원 N개 → 내 해낼게 관리" 바 노출(→`/home`). 페이지 본체는 친구용 그대로(내 페이지 미리보기 가치 겸함). 심리=손실회피(미확인 응원 상기).

| 시나리오/상태 | 트리거 | 경로 (dead-end 0) |
|---|---|---|
| **인스타 바이오 자기링크(최빈)** | 본인이 `/g/[slug]` 탭 | 본인 세션 → owner bar → `/home` |
| 위 + 세션 없음 | 로그아웃/새 기기 | 친구용 화면 + footer subtle "내 목표가 있으신가요? 로그인" → 카카오 로그인 → `/home` |
| 북마크/직접입력 | `/home` 진입 | 세션 有→홈 / 無→로그인→`/home` |
| 타인 목표 열람 | 로그인 상태로 남의 `/g/[slug]` | owner bar 없음(친구용 그대로 — 제3자 비노출 유지) |
| 세션 만료 중 owner 접근 | 만료 | error 카드: 재로그인 유도, 친구용 열람은 유지 |
| 응원 0 (empty) | 재방문했는데 빈 목록 | owner bar 문구 = "받은 응원을 여기서 관리해요" / `/home`은 기존 empty(링크 복사 유도) |
| 목록 로드 실패 | 네트워크 | `/home` error 카드 "다시 불러오기"(잔액 표시는 유지) |
| 목표 삭제 후 재방문 | 본인 | "종료된 목표" + 새 목표 만들기(`/onboarding`) |

**갭2 — 개별 금액 본인 노출 (🔒 회장 결정 B, 2026-07-19):** `/home` "응원한 사람" 목록에 응원별 **클로버 개수(🍀 N)** 를 행 우측 메타로 표기. Discreet 유지 장치 = 시간순 고정(정렬·랭킹 UI 금지) · ₩ 환산 없음 · 익명 응원도 개수는 표시(익명=신원 은닉이지 본인 수입 은닉 아님) · 제3자/공개 화면은 종전대로 완전 비노출. §1.1-6의 "금액은 안 봄"은 이 결정으로 대체됨(DESIGN.md §6-b′ 정본).

## 2. 친구 플로우 (② 목표 페이지 → 조용한 결제)

### 2.1 Happy path
1. **유입** — 인스타 링크 클릭 → ② 도경 목표 페이지 도착. 🔒 **비로그인 열람 가능**(로그인 벽 없음).
2. **열람** — GoalCard(목표·왜·D-day) + CheerCount("N명이 응원") + 워드맵. 🔒 금액 비노출.
3. **응원 시작** — primary CTA "조용히 밀어줄게" → PaymentSheet(바텀시트) 슬라이드업.
4. **금액 선택** — AmountChips 커피값 앵커(3·5·10천 + 직접). ⚠️ 기본값 낮게(다크패턴 금지).
5. **메시지(선택)** — MessageField 한 줄 응원. 🔒 비동기·안 써도 됨. placeholder="안 써도 돼요. 마음만 닿아요".
6. **익명 선택** — AnonymityToggle 이름 노출 ↔ 익명. 🔒 응원자 선택(Q2 강제익명 철회).
7. **결제** — 🔒 **그 자리에서 직접 결제(사전 충전 X)**. 🔒 로그인 최소(간편결제/게스트 ❓§5-5). 처리중 로딩 표시.
8. **완료** — ConfirmToast 은은한 확인("도경이에게 조용히 닿았어요"). 🔒 감사답장 기다림 없음.
9. **(확산)** — 완료 화면 하단 subtle "나도 해낼게 만들래" → ① 온보딩(role-transition). ⚠️ subtle, primary 아님.

### 2.2 ② 분기·상태 (dead-end 0 — 콜드스타트 생사 화면)
| 상태 | 트리거 | 화면/다음 경로 |
|---|---|---|
| **empty(응원 0)** | 첫 방문자, 워드맵 빔 | EmptyState: "아직 아무도 없어요. 당신이 첫 응원이에요." 워드맵 자리에 초대 카피. **첫 친구가 누르게 설계**(콜드스타트 윤활). |
| few(1~5) | 초기 | 작은 워드맵 + "○○님이 첫 응원을 보냈어요" |
| 비로그인 열람 | 링크 직클릭 | 전부 보임. 결제 누르면 그때만 최소 인증(❓ 게스트면 인증 스킵) |
| 결제 시트 닫음 | 사용자 취소 | 페이지 복귀, 잃는 것 없음. 재진입 가능 |
| **결제 처리중** | 결제 호출 | 시트 로딩 상태(버튼 spinner, 닫기 잠금) — 침묵 금지 |
| **결제 성공** | PG 승인 | ConfirmToast + 워드맵에 내 메시지 반영(익명선택 반영) |
| **결제 실패** | PG 거절·한도·네트워크 | ErrorState 카드: 사유 한 줄 + "다시 시도" + "다른 결제수단". dead-end 아님 |
| 결제 중복/이중탭 | 빠른 더블탭 | 버튼 잠금으로 멱등 처리(중복결제 방지) |
| **환불 요청** | 결제 후 변심·오류 | ⚠️ MVP UI 최소 = 완료 toast/영수증에 "문의" 경로(고객센터). 자동환불 정책 ❓(eng/legal) |
| **목표 마감됨** | D-day 경과 | "마감된 목표" 칩. 🔒 적립형이라 **응원 여전히 가능**(❓§5-4 회장 확인) |
| **목표 비공개/삭제** | 주인공이 내림 | "종료된 목표예요" 안내 + "다른 목표 만들기"(① 진입) — 빈 404 금지 |
| 잘못된 링크 | 오타·만료 슬러그 | 친절한 404 + 홈(① 랜딩) 링크 |
| **셀프후원 의심** | 동일인 결제↔환전 추정 | ⚠️ 결제는 막지 않되 환전측 KYC·이상거래로 차단(§5-5·risks#8). UI=환전 단계 검증 |
| 미성년 결제 | 결제수단 미성년 | 법정대리인 동의 안내(risks#7). 정책 ❓§5-4 |

## 3. 두 플로우의 접합 (확산 루프 — dead-end 0 검증)

```
① 도경 목표생성 → 링크 → 인스타 바이오
         │
인스타 눈팅 민지 ─클릭─▶ ② 도경 페이지
         │ (empty면 "첫 응원" / 차있으면 워드맵)
         ▼ "조용히 밀어줄게" → 금액 → (메시지) → (익명) → 결제 → 완료 toast
         │
         ├─▶ 워드맵 갱신 → 도경이 재공유 → 다음 친구 ②유입 (확산)
         └─▶ 완료화면 subtle "나도 만들래" → ① 온보딩 (역할전환=신규 공급)
```
모든 노드에서 막다른 길 없음: empty도 초대로, 실패도 재시도로, 마감도 응원지속으로, 비공개도 ①진입으로 회수.

## 6. MVP 스코프 경계 — 의식적 제외 (빼먹은 게 아니라 뺀 것)

> 🔒 회장 확정(2026-07-03). 아래 3건은 **설계를 안 한 게 아니라, MVP에서 의도적으로 제외**한 것. coverage ❌0의 정의 = **"MVP 스코프 내 전수"** — 스코프 밖은 미커버(❌)가 아니라 *제외*다.

| # | 제외 항목 | 왜 뺐나 | 재검토 시점 |
|---|---|---|---|
| 1 | **마일스톤 pledge**("해내면 쏜다" 조건부 후원, PRD F4·bm 보조1순위) | 콜드스타트는 **커피값 즉시 응원**으로 돈다. pledge는 고액·고복잡(달성 조건부 지급·에스크로·판정) → MVP 코어 루프를 무겁게 함 | **시장검증(컨시어지 콜드스타트) 후** 재검토 |
| 2 | **admin(운영자) 화면** | 환전 승인·KYC 검토·어뷰징 차단·신고·CS는 MVP에선 **수동/내부 처리**로 감당. 풀 admin UI는 과투자 | **build 이후**(운영량이 수동 한계 넘을 때) |
| 3 | **목표 달성('해냄') 흐름** | 적립형은 **달성 무관 환전**(🔒). "해냄 인증→보상" 루프는 즉시 응원·적립·환전 코어와 독립 → MVP는 **즉시 응원 적립·환전 루프만** | pledge(#1)와 함께 재검토(달성 판정이 필요해지는 시점) |

**스코프 안(설계 완료):** ① 가입·목표생성·링크 / ② 열람·즉시 응원 결제(게스트·전부유료·익명표시) / 워드맵·공유 확산 / 받는사람 홈·수신 / 환전·정산 / 엣지·에러. → coverage.md 전수.
**연결 무결:** 위 3건을 빼도 dead-end 없음 — 마감 목표는 응원 지속(달성흐름 불필요), 환전은 적립형 단독 동작, pledge 없이 커피값 즉시 응원으로 코어 루프 완결.
