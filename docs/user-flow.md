## 0. 두 행위자 · 두 화면 (절대 분리 — 이전 혼선 지점)

| | 받는 사람 (주인공·공급) | 친구 (응원자·수요) |
|---|---|---|
| 목적 | 목표 선언하고 조용히 응원받기 | 친구 목표에 조용히 돈으로 응원 |
| 화면 | **① 가입 랜딩 + 목표 만들기** | **② 목표 페이지(공유 링크 타깃)** |
| 진입 | 입소문/공스타 운영계정 linktree | **인스타 바이오 링크 → ②로 직행** |
| 결과 | 클로버 적립 → 환전 | 결제(매출 발생) |

**핵심 교정(컨트롤러 draft 비판):** 친구는 **① 랜딩(홈)에 오지 않는다.** 인스타 링크는 항상 **②(특정 사람의 목표 페이지)** 로 떨어진다. 따라서 ①에는 "친구 응원하러 왔어요" CTA를 두지 않는다. 친구→자기목표 전환(role-transition)은 **②→①** 한 방향으로만 흐른다(②에서 "나도 해낼게 만들래" → ① 온보딩). 이게 자가확산 공급 고리의 진짜 입구다.

```
인스타 바이오 ─클릭─▶ ② 도경의 목표 페이지 ─결제─▶ (확산) ─"나도 만들래"─▶ ① 온보딩 ─내 링크─▶ 인스타 바이오 …
```

## 1. 받는 사람 플로우 (① 가입 → 목표 → 링크 → 수신 → 워드맵 → 환전)

### 1.1 Happy path
1. **진입** — 공스타 운영계정/프로필 linktree, 또는 ②에서 "나도 만들래" 전환. 🔒 1차 GTM=공스타 linktree.
2. **랜딩(①)** — 🔒 확정 = **C 미니멀 + 워드맵 프리뷰 하이브리드**(`landing-final.html`). 슬로건 히어로(궁금증 훅) + 컴팩트 워드맵 프리뷰(받는사람 보상 미리보기). primary CTA "시작하기" **단 하나** + 보조 "어떻게 쓰는 건가요?". (친구 CTA 없음)
3. **목표 만들기** — 🔒 입력 = 목표("○○ 해낼게")·일정(D-day)·왜(이유). 매일 인증 강제 X(진행 업데이트는 선택).
   - 🔒 가입 방식 확정 = **write-first**: 시작하기 → 목표쓰기(=C가 못 한 설명 역할) → "저장" 누를 때 AuthSheet(소셜 1탭).
4. **저장/로그인** — AuthSheet(소셜 1탭). ⚠️ write-first면 입력 draft를 로컬에 보존(로그인 실패해도 글 안 날아감).
5. **내 링크 받기** — 고유 링크 발급 → ShareLinkCard: 복사 + "인스타 바이오에 붙여넣기" 안내. 🔒 공급 활성화 핵심 한 스텝.
6. **대기/수신** — 친구 응원 도착 → 🔒 은은한 알림(감사답장 의무 없음). 누가 응원했는지 봄(🔒 익명 강제 아님), 금액은 안 봄(🔒).
7. **워드맵 → 공유(확산 고리)** — 홈은 "워드맵 보기" 단일 CTA → **워드맵 풀뷰**(꽉 찬) → **아이콘 공유**(텍스트 X): 이미지 저장 / 인스타 스토리(목표 링크 스티커 얹힘) / 링크 복사 → 친구가 스토리 보고 링크 탭 → ② 목표페이지 도착 = 🔒 확산 고리 닫힘. 워드맵은 단어·"익명의 누군가"만, 개별 후원 금액 X. (프로토 `wordmap-share.html`)
8. **환전**: 🔒 **총보유 클로버(웰컴 포함)가 30개 이상이면 환전 자격에 도달**한다. 실제 신청량은 웰컴을 뺀 **지급가능 클로버 1개 이상, 지급가능 잔액 이하**다. 따라서 총보유 30개가 `친구 응원분 27 + 웰컴 3`으로 구성된 회원은 **27개를 신청할 수 있다.** 신청량을 원화로 환산한 뒤 서비스 이용료 10%와 그 부가세, 사업소득 원천징수 3.3%를 차감한다(계산식 정본 = DESIGN.md §6-(c)). (적립형=달성 무관 환전 🔒)
   - 🔒 **신청해도 클로버 총량은 줄지 않는다(2026-08-21 회장 확정 A안).** 신청분에 **잠금**이 걸릴 뿐이고, 총량에서 실제로 빠지는 시점은 **입금이 완료된 때** 하나뿐이다. 반려·이체실패는 잠금만 풀며, 총량은 애초에 변하지 않았으므로 되돌릴 것이 없다. 화면은 총량 아래에 "지금 쓸 수 있어요 / 🔒 환전으로 잠김"을 분할해 보여주고(DESIGN.md §6-(d)), 총량이 줄어드는 입금 완료 시점에는 그 이유를 먼저 설명한다. 전체 여정 프로토=`docs/prototype/core-cashout-full-journey-v3.8-opus5.html` v3.8, 30/27 경계 정본=`docs/prototype/core-cashout-30-27-v1-gpt-codex.html` v1.0.0.
   - 🔒 **금액 표기 3층(2026-07-02 확정):** 친구/공개=비노출("N명"), 받는사람 본인 홈·워드맵=클로버 **개수(🍀 N개)만**(₩ 환산 X), **원화는 환전 플로우에서만** 현실화(진입=개수, 환전 눌러야 ₩·수수료 등장). DESIGN.md §6 정본.

### 1.2 ① 분기·상태 (dead-end 0)
| 상태 | 트리거 | 화면/다음 경로 |
|---|---|---|
| 입력 검증 실패 | 목표 빈값·일정 과거 | 인라인 에러, 저장 비활성, 채우면 복구 |
| 로그인 취소/실패 | AuthSheet 닫음·소셜 거부 | draft 유지 + "나중에 저장" → 로컬 보존, 재시도 경로 |
| 링크 복사 직후 공백 | 응원 0 | "이제 인스타에 붙여보세요" 가이드(= ②의 empty와 연결) |
| 알림 수신 | 응원 도착 | 은은한 배지. 답장 강요 없음. 무시 가능(dead-end 아님) |
| **환전 자격 미달** | 총보유(웰컴 포함) < 30개 | "조금만 더 모으면 환전할 수 있어요" + `30 − 총보유` 남은 개수. 막다른 길이 아니라 대기 상태 |
| **환전 경계 30/27** | 총보유 30개 · 웰컴 3개 · 지급가능 27개 | 자격 도달로 신청 폼을 연다. 분해표에 30/3/27을 함께 보여주고, 입력 기본값·최댓값은 27개다. "친구 응원분 30개부터" 또는 "신청 최소 30개" 문구 금지 |
| **자격 도달·지급가능 0** | 총보유 ≥ 30개이나 지급가능 0개 | 신청 CTA 비활성 + "웰컴 클로버는 환전되지 않아요. 친구 응원이 들어오면 신청할 수 있어요" + 홈으로. 0개 신청 화면으로 보내지 않는다 |
| **연령 확인 기록 없음** | 가입 직후 환전 시도 | 신청 허용. 주민등록번호는 실제 지급 단계에서 수집한다 |
| **확인된 미성년** | 최신 KYC 결과 `is_adult=false` | 신청 차단 + "미성년으로 확인된 계정은 환전을 신청할 수 없어요" + 홈으로 |
| **환전 신청 접수(잠김 발생)** | 신청 확정 | 총량 유지 + 분할 표시("쓸 수 있어요 N개 / 🔒 잠김 N개"). 재신청은 차단하되 진행 상태로 보낸다 |
| **환전 반려·이체 실패** | 관리자 반려·은행 반송 | 잠금 해제. 총량은 처음부터 그대로이므로 "돌아왔어요"가 아니라 **"잠금이 풀렸어요"**로 안내 + 계좌 고쳐 재신청 |
| **입금 완료(총량 감소)** | 관리자 지급 확정 | **총량이 줄어드는 유일한 지점.** "잠겨 있던 N개는 이 돈으로 바뀌었어요"로 이유를 먼저 말하고 환전 내역(누적 받은 금액)으로 회수 경로를 준다 |
| **목표 마감(D-day 경과)** | 일정 지남 | 🔒 적립형=달성 무관 환전 가능. 페이지는 "마감됨" 칩, **응원 계속 가능**(🔒 §5.4-6 확정) |
| 계정/목표 삭제 | 본인 삭제 | 확인 모달 → 삭제 시 링크는 "종료된 목표" 안내(②에서 404 아님) |

### 1.3 받는사람 재방문·관리 진입 (2026-07-19 보완 — 갭1·갭2, 회장 승인)

> 실측 갭: 목표 주인이 자기 공개링크(`/g/[slug]`)를 열면 친구용 화면만 보였다. 현재 관리 홈은 별도 `/home` 라우트가 아니라 `/me`다.
> 프로토: `WIREFRAMES/haenael-receiver-manage-v1-fable.html` (라우팅 허브 — 화면·뷰포트·상태 토글).

**진입 동선 확정안 = (a)+(b) 조합** ((c) 전역 헤더는 MVP 보류 — 공개 화면 단일 CTA·Discreet 훼손):
- **(a) 세션 라우팅**: `/` 진입 시 세션 有+목표 有 → `/me` 리다이렉트, 세션 有+목표 無 → 랜딩에서 `/onboarding` 진입, 세션 無 → ① 랜딩. 코드 기준 관리 홈은 `/me`다.
- **(b) owner bar**: 본인 세션으로 `/g/[slug]` 열람 시 상단에 "내 목표예요 · 확인 안 한 응원 N개 → 내 해낼게 관리" 바를 노출하고 `/me`로 연결한다. 페이지 본체는 친구용 그대로다.

| 시나리오/상태 | 트리거 | 경로 (dead-end 0) |
|---|---|---|
| **인스타 바이오 자기링크(최빈)** | 본인이 `/g/[slug]` 탭 | 본인 세션 → owner bar → `/me` |

## 2. 친구 플로우 (② 목표 페이지 → 조용한 결제)

### 2.1 Happy path
1. **유입** — 인스타 링크 클릭 → ② 도경 목표 페이지 도착. 🔒 **비로그인 열람 가능**(로그인 벽 없음).
2. **열람** — GoalCard(목표·왜·D-day) + CheerCount("N명이 응원") + 워드맵. 🔒 금액 비노출.
3. **응원 시작** — primary CTA "조용히 밀어줄게" → PaymentSheet(바텀시트) 슬라이드업.
4. **금액 선택** — AmountChips 커피값 앵커(3·5·10천 + 직접). ⚠️ 기본값 낮게(다크패턴 금지).
5. **메시지(선택)** — MessageField 한 줄 응원. 🔒 비동기·안 써도 됨. placeholder="안 써도 돼요. 마음만 닿아요".
6. **익명 선택** — AnonymityToggle 이름 노출 ↔ 익명. 🔒 응원자 선택(Q2 강제익명 철회).
7. **결제** — 🔒 **그 자리에서 직접 결제(사전 충전 X)**. 🔒 로그인 최소(간편결제·게스트 허용, §5.4-4 확정). 처리중 로딩 표시.
8. **완료** — ConfirmToast 은은한 확인("도경이에게 조용히 닿았어요"). 🔒 감사답장 기다림 없음.
9. **(확산)** — 완료 화면 하단 subtle "나도 해낼게 만들래" → ① 온보딩(role-transition). ⚠️ subtle, primary 아님.

### 2.2 ② 분기·상태 (dead-end 0 — 콜드스타트 생사 화면)
| 상태 | 트리거 | 화면/다음 경로 |
|---|---|---|
| **empty(응원 0)** | 첫 방문자, 워드맵 빔 | EmptyState: "아직 아무도 없어요. 당신이 첫 응원이에요." 워드맵 자리에 초대 카피. **첫 친구가 누르게 설계**(콜드스타트 윤활). |
| few(1~5) | 초기 | 작은 워드맵 + "○○님이 첫 응원을 보냈어요" |
| 비로그인 열람 | 링크 직클릭 | 전부 보임. 게스트 결제라 앱 가입 없이 간편결제로 바로 진행(§5.4-4 확정) |
| 결제 시트 닫음 | 사용자 취소 | 페이지 복귀, 잃는 것 없음. 재진입 가능 |

## 3. 두 플로우의 접합 (확산 루프 — dead-end 0 검증)

```
① 도경 목표생성 → 링크 → 인스타 바이오
         │
인스타 눈팅 민지 ─클릭─▶ ② 도경 페이지
         │ (empty면 "첫 응원" / 차있으면 워드맵)
         ▼ "조용히 밀어줄게" → 금액 → (메시지) → (익명) → 결제 → 완료 toast
         │
         ├─▶ 워드맵 갱신 → 도경이 재공유 → 다음 친구 ②유입 (확산)

```

### 5.5 기술설계 인계 (A안이 요구하는 상태값)

화면이 요구하는 것만 적는다. 설계는 eng-design 몫이다.

| 화면이 필요로 하는 값 | 언제 변하나 |
|---|---|
| **총 클로버**(모인 클로버) | 신청·반려·이체실패에 **불변**. **입금 완료 시점에만** 잠긴 만큼 감소 |
| **잠긴 클로버** | 신청 접수 시 +N. 반려·이체실패 시 0으로 해제. 입금 완료 시 0(총량으로 확정 차감되며 소멸) |
| **사용 가능 클로버** | 항상 `총량 − 잠김`. 화면이 직접 계산하지 않고 값으로 받는다 |
| **지급가능 클로버** | 웰컴과 잠김을 제외한 실제 신청 상한. 자격 도달 여부와 별도 값이다 |
| **환전 자격 도달** | `총보유 ≥ 최소 기준(30)`. 지급가능분이 30 미만이어도 참일 수 있다 |

**화면이 절대 깨지면 안 되는 불변식**
1. `사용 가능 = 총 클로버 − 잠긴 클로버`가 모든 상태에서 성립한다. 한 순간이라도 어긋나면 분할 막대와 두 라벨이 서로 다른 말을 한다.
2. `잠긴 클로버 ≤ 총 클로버`. 음수 사용 가능이 화면에 뜨면 안 된다.
3. 동시에 진행 중인 환전은 1건이므로 잠김도 1건분이다(재신청 차단이 이 전제를 지킨다).
4. 총 클로버가 감소하는 이벤트는 **입금 완료 하나뿐**이다. 다른 경로로 총량이 줄면 화면의 "모은 개수는 그대로예요" 약속이 깨진다.
5. 잠긴 클로버에는 확정된 실지급 원화(`받으실 금액`)가 붙어 있어야 한다. 잠김 행이 "N원 입금 예정"을 표시하기 때문이다.
6. `환전 자격 도달 = 총보유 ≥ 30`, `1 ≤ 신청량 ≤ 지급가능`을 별도로 판정한다. 신청량에 30개 하한을 다시 적용하면 30/27 경계 사용자를 잘못 막는다.
