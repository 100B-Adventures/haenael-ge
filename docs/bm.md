# 해낼게 비즈니스 모델

> **한 줄 결론:** 응원자가 결제한 클로버는 받는 사람에게 즉시 적립되고, 받는 사람이 환전할 때 원화 환산액의 서비스 이용료 10%와 그 이용료의 부가가치세를 차감한다.

## 1. 현행 돈의 흐름

| 단계 | 현행 계약 | 제품 판정 |
|---|---|---|
| 응원 결제 | 1클로버는 1,000원 상당이다. 응원 결제가 성공하면 조건 없이 받는 사람 계정에 적립한다 | 목표 달성 판정과 무관한 **즉시 적립형 응원** |
| 환전 자격 | 웰컴 등 시스템 지급분을 포함한 **총보유 30클로버 이상** | `total_clover >= 30` |
| 신청 가능액 | 친구 응원분에서 잠김을 뺀 **지급가능 클로버 1개 이상, 지급가능 잔액 이하** | `1 <= requested_clover <= payable_clover` |
| 신청 시점 | 총량은 줄지 않고 신청량만 잠긴다 | 중복 사용 방지, A안 잠금 유지 |
| 지급 시점 | 입금 완료 때 잠긴 클로버가 총량에서 빠진다 | 총량 감소의 유일한 시점 |
| 매출 | 원화 환산액의 서비스 이용료 10% | 해낼게 매출의 현재 정본 |
| 부가세 | 서비스 이용료의 10%를 별도 가산해 차감 | 이용료 10%와 혼동 금지 |
| 원천징수 | 이용료와 부가세를 뺀 금액의 3.3%를 현행 계산 | 법적 적용 근거와 주체는 세무 검토 필요 |

### 30 대 27 대표 경계

총보유가 30클로버이고 그중 웰컴 3클로버가 포함돼 지급가능액이 27클로버라면 환전 자격은 충족한다. 신청액은 27클로버까지 허용한다. 신청량에 다시 30클로버 하한을 적용하지 않는다.

30클로버를 신청하는 현행 기준값은 다음과 같다.

| 항목 | 금액 |
|---|---:|
| 원화 환산액 | 30,000원 |
| 서비스 이용료 10% | 3,000원 |
| 이용료 부가세 10% | 300원 |
| 원천징수 3.3% | 881원 |
| 실수령액 | 25,819원 |

## 2. 매출 구조

### 2.1 현재 매출원

현재 매출원은 환전 시 차감하는 **서비스 이용료 10%** 하나다. PG 비용, 환불 비용, 알림 비용, 수동 지급과 CS 노동은 이 10% 안에서 감당해야 하므로 매출과 공헌이익을 같은 숫자로 보고하지 않는다.

### 2.2 현재 범위 밖 후보

| 후보 | 상태 | 다시 검토할 조건 |
|---|---|---|
| 조건부 또는 마일스톤 pledge | **범위 밖** | 즉시 적립형 응원의 결제 전환·반복률이 검증되고, 달성 판정·환불·사행성·약관 문제를 별도 PRD로 합의할 때 |
| 기업 스폰서 응원 | 후행 후보 | 목표 선언자 공급과 카테고리별 전환 데이터가 충분할 때 |
| 구독 또는 멤버십 | 후행 후보 | 반복 응원자가 월 단위 편의를 실제로 요구할 때 |

조건부 pledge는 현재 응원금의 지급 조건이 아니다. 목표 달성 실패 시 환원·소멸하는 로직도 현행 제품에는 없다.

## 3. 외부 벤치마크와 차용 범위

| 벤치마크 | 확인한 사실 | 차용 | 차용하지 않는 것 |
|---|---|---|---|
| 투네이션 공식 수수료 안내 | 결제수단별 PG·이용 수수료가 다르고, 원천세는 정산 유형에 따라 달라진다 | 결제수단별 직접비와 세무 유형을 분리해 계산 | 과거 단일 6.3%를 현재 all-in 천장으로 고정하는 설명 |
| Patreon 공식 Creator fees | 신규 표준 플랜은 플랫폼 수수료 10%에 결제 처리비·지급비·적용 세금이 별도로 붙는다 | 플랫폼 이용료와 결제·지급 직접비를 분리하는 손익 구조 | 구독 중심 제품 구조와 해외 세율을 그대로 복제 |
| Stripe 공식 Balance 문서 | 지급 가능 전 금액과 지급 가능한 금액을 `pending`과 `available`로 분리한다 | 총보유·잠김·지급가능을 나눠 보여주는 원리 | Stripe Connect 도입을 이미 결정한 것처럼 서술 |

**차별화:** 투네이션과 Patreon은 크리에이터와 팬 관계가 중심이다. 해낼게는 지인 관계에서 금액을 과시하지 않고 목표 과정에 즉시 적립하는 것이 핵심이다.

## 4. 단위경제 판정식

| 지표 | 계산 | 현재 상태 |
|---|---|---|
| GMV | 성공 결제 원금 합계 | 운영 유료 루프 표본 부족 |
| 매출 | 환전 원화 환산액 × 10% | 정책 확정 |
| 건당 공헌이익 | 이용료 매출 - PG - 환불 - 알림 - 지급·CS 직접비 | 미검증 |
| 응원자 반복률 | 첫 결제 성공자 중 4주 내 2회차 성공자 비율 | 미검증 |
| LTV/CAC | 응원자 공헌이익 누계 / 응원자 획득비 | 미검증 |

## 5. BM 종료 기준

1. **결제 전환:** 유료 결제 재개 뒤 4주, `cheer_started`를 발생시킨 고유 응원자 50명 이상에서 결제 성공률이 40% 미만이면 결제 플로우와 One Thing을 재검토한다.
2. **반복 응원:** 첫 결제 성공자 50명 이상을 4주 추적했을 때 2회차 응원 성공률이 10% 미만이면 반복 매출 가정을 폐기한다.
3. **공헌이익:** 유료 결제 재개 후 8주 또는 성공 결제 30건 도달 시점 중 늦은 때, 전건 평균 공헌이익이 0원 이하이거나 LTV/CAC가 1.0 미만이면 유료 유입을 중단한다.

모집단 최소치에 도달하지 못한 경우는 성공이 아니라 데이터 부족이다. 이때 유료 확장과 신규 BM 추가를 보류한다.

## 6. 운영과 규제 경계

- KYC 기록이 없는 가입자도 환전 신청은 가능하다. 최신 확인 결과가 미성년인 계정만 신청을 차단한다.
- 주민등록번호는 실제 지급 단계에서 수집한다. 수집·보관·파기 방식은 법률 검토가 필요하다.
- 원천징수 3.3%가 모든 수취인에게 동일하게 적용되는지, 지급명세 의무 주체가 누구인지는 세무 검토가 필요하다.
- 클로버와 환전 구조가 전자금융거래법상 어떤 지위인지 변호사 검토 전 확정하지 않는다.

## 7. 레드팀과 셀프심문

**회의적 투자자 공격:** 10% 이용료를 확정해도 소액 결제의 PG 비용과 수동 지급 노동을 빼면 남는 돈이 없을 수 있다. 응원자가 한 번만 결제하고 재방문하지 않으면 GMV가 늘수록 운영 부하만 커진다. 그래서 총매출이 아니라 건당 공헌이익과 4주 반복률을 종료 기준으로 둔다.

**이 결론이 틀렸다면 가장 그럴듯한 이유:** 사용자에게 중요한 것은 즉시 적립이 아니라 "성공하면 받는 보상"일 수 있다. 그러나 현행 운영과 UI는 이미 즉시 적립형이며 조건부 계약·환불·달성 심사가 없다. 이 가설을 이유로 pledge를 현행 BM처럼 쓰지 않고 별도 PRD가 필요한 범위 밖 후보로 내린다.
