한 장 지도사용자가 보는 것, 회장이 하는 것, DB에 남는 것을 같은 시간축에 놓았습니다. 칸을 클릭하면 그 화면으로 갑니다. 모바일에서는 3개 레인이 세로로 분리되고 각 칸에 시점 라벨이 붙습니다.

"이미 처리 중인 신청이 있어요"와 진행 상태로 이동하는 버튼. 막고 끝내지 않고 갈 곳을 줍니다

사용자 화면 회장 액션 DB·원장 분기·실패 모은 클로버 총량은 신청해도 줄지 않습니다. 신청분에 잠금이 걸렸다가, 입금이 끝난 때 총량에서 빠지고, 반려되면 잠금이 풀립니다.

사용자/me 마이페이지 모바일은 단일 컬럼입니다. 환전 진입은 클로버 잔액 카드 안에 둡니다(별도 섹션 없음). 데스크톱은 2단입니다. 좌측에 목표와 응원한 사람, 우측 레일에 잔액·환전 진입·내역을 고정합니다.

v3.6 이번 개정 (회장 A안 확정 반영)

  • 진행중 상태에서 총량이 52개로 유지됩니다. 이전에는 신청 직후 12개로 떨어졌습니다. 회장 원문: "A안이지 실제로 빠져나갔을때 빠져나가야지" (2026-08-21)
  • 분할 잔액 컴포넌트 신설(이번 턴의 실질 과제). A안의 약점은 "총량 52인데 쓸 수 있는 건 12"라 숫자 하나가 두 뜻을 갖는 것입니다. 총량 아래에 분할 막대 + 두 줄 라벨("지금 쓸 수 있어요 🍀 12개" / "🔒 환전으로 잠김 🍀 40개")을 붙여 전체를 눈에 보이게 쪼갰습니다. 은행 앱의 current balance / available balance 2단 표기와 같은 구조이고, 막대가 비율을 먼저 주기 때문에 글을 읽지 않아도 관계가 잡힙니다. 잠김이 0이면 이 블록은 통째로 사라집니다.
  • 진행중일 때 총량 옆 원화 등가("≈52,000원 상당")를 감춥니다. 잠긴 40개는 이미 실수령 34,426원으로 확정돼 있어서, 등가와 실수령이 같은 카드에 나란히 뜨면 금액 계층이 섞입니다(DESIGN.md §6-c). 대신 등가는 분할 행 각각에 붙였습니다.
  • 입금 완료 배너를 다시 썼습니다. A안에서는 이때 총량이 52→12로 줄어듭니다. 놀람이 되지 않게 "잠겨 있던 40개는 이 돈으로 바뀌었어요. 그래서 모인 클로버가 52개에서 12개가 됐어요"로 이유를 먼저 말하고, 사라진 것이 아니라 환전 내역에 남는다는 회수 경로를 붙였습니다.

셀프심문 이 결론이 틀렸다면 가장 그럴듯한 이유는 27개 신청이 기술적으로만 가능하고 사용자는 화면의 "30개"를 신청량 하한으로 읽는다는 점입니다. 이를 막기 위해 30/27 상태를 별도 토글로 렌더하고 "환전 기준"과 "지금 지급 가능"을 각각 이름 붙였습니다.
